# prereg-first — 预注册先于付费

> 状态：L1 已完成（2026-10-26）。检查脚本第一批已实现。

## 1. 一句话规则

判定线、身份、发车登记先写死并签字，然后才允许花钱跑批。

## 2. 为什么

判定线是发车后才补的，人就会在看到数字之后"顺手"调整过关标准——
败仗被解释成"本来就是探针"，胜仗被解释成"预注册有远见"。
预注册的唯一作用就是把"事前"和"事后"在物理上分开：线写死在先、
数字落在后，任何事后挪线都会在 SHA 对不上时暴露。

## 3. 细则

1. **判定线写死且含失败分支**：主口径、分母、达标区间、未达线时的
   强制动作（如 <32% 回查线）都必须在预注册文本里，不能只写目标不写
   未达线怎么办（先例：T-H 预注册同时写 35–40% 线与 <32% 回查线）。
2. **发车前置件逐项核验后才 launch**：预注册 SHA、发车书 SHA、
   脚本锁、批准包、budget 文件、env 存在性——缺一件就停，先补齐再走
   （先例：P2 批准包缺 `budget_no_cap.json`，prepare 直接 rc=1）。
3. **DRAFT 不是授权**：预注册 `DRAFT_NOT_SIGNED`、发车书
   `DRAFT_NOT_EXECUTABLE` 状态下，任何报告都不能被当成发车授权消费。
4. **现场保护写进预注册**：stop.json「首写生效、现场不删改」、
   封存批只读、阈值零改动——这些纪律本身是预注册条款的一部分，
   不是跑完批再补的 etiquette。
5. **发车登记一次写死**：batch_tag、臂定义、模型、env、token 门
   在发车前落字并锁 SHA；确需变更走新版本文书并披露 deviation，
   不静默改旧件。
6. **代决必须留 provenance 与后置复核项**：授权链中断（如 Codex 无
   额度）时由代审执行，须逐字登记代决身份与 CC 后置复核清单，
   不伪填签名人。

## 4. 反例

反例：launch 未导出必需环境变量，首投作业把 83 个文件写进臂根
（`docs/T_P2_FORMAL_BUILD_PREPARE_2026-10-21.md:80`，偏差登记
`:233`）
发生什么 → `launch --phase build` 只导出 `WS/CODE/BATCH_ROOT/...`，
未导出 `QUESTIONS/V3_CODE_ROOT`，`sbatch_p2_build.sh` 的 guard 因此
进入 arm-env 分支，把 `BATCH_ROOT` 覆盖成臂根；作业 `47083951` 把
83 个文件写进了 `p2_298_20261021_v1card` 臂根，seed 根未创建。
→ 后果：作业被本会话取消，部分根整体隔离进 quarantine；修复靠
发车前手工补导出变量 + 建符号链接，且「后续任何人直接 launch 仍会
复现」——操作链缺陷被如实登记为 D1，留待另行授权修复。
→ 正确做法：发车前把 launch 入口当作预注册身份面的一部分核验
（导出变量清单、guard 分支、seed/臂根互斥），发现缺陷先修入口，
不用「本次绕过」换发车。

反例：批准包缺 `budget_no_cap.json`，prepare 首次 rc=1
（`docs/T_P2_FORMAL_BUILD_PREPARE_2026-10-21.md:60`，偏差 D3 `:235`）
发生什么 → 批准记录目录漏了费用文件，`prepare` 直接失败。
→ 后果：发车链中断一次；补齐用的是官方命令
`p2_operations.py no-cap --arm v1card --create`（带 marker 与 SHA），
原 `SHA256SUMS` 未包含新文件这一事实被如实披露。
→ 正确做法：前置件清单在发车登记里逐项列出并核存在性；缺件走
官方补录通道并留 SHA，不走手工伪造。

反例：停点后想省时间原地 resume / 放宽阈值，均被预注册条款拦住
（`docs/T_I_B3_STOP_TRIAGE_2026-10-21.md:53`、`:54`）
发生什么 → B3 smoke10 一题传输失败停两臂后，选项 B（清 stop、
原地重试）会改已停现场、违反「现场不删改」；选项 C（失败题留分母
继续 full）需要绕过 smoke10 阈值，「当前授权不允许」。
→ 后果：两条捷径都被否，唯一合规路径是 B4 新批（新 tag/新根/
新协调目录）。
→ 正确做法：预注册里写死「现场不删改 + 阈值零改动」，停点后的
选项表按这两条过滤；想改阈值就另立预注册，不就地变通。

## 5. 检查清单

开工前：
- [ ] 本轮是「新阶段实施」还是「回修轮」？新阶段先写任务书与预注册，回修轮按常设循环走。
- [ ] 判定线（主口径/分母/达标区间/未达线动作）有没有全部落字？
- [ ] 单变量还是合批？合批须在预注册里写明不可单变量归因（见 `batch-discipline`）。

发车前：
- [ ] 预注册/发车书/化学复审/脚本锁四文书 SHA 齐且互相绑定？
- [ ] 批准包、budget 文件、env 存在性与权限核过？
- [ ] 发车入口（脚本 guard、导出变量、seed/臂根互斥）实跑过一次干跑或复核过？
- [ ] 状态不是 DRAFT_NOT_SIGNED / DRAFT_NOT_EXECUTABLE？
- [ ] 现场保护条款（stop 不可删改、旧批 immutable、封存只读）已进文本？

交付后：
- [ ] 结果报告开头有预注册指针与判定线原文？
- [ ] 未达线时强制回查执行了（见 `stop-loss-gate`）？
- [ ] 全部 deviation（绕过、补录、代决）登记在偏差表并标 CC 复核项？

## 6. 机器检查

脚本：`scripts/bible_checks/check_prereg_first.py`（第一批已实现）。

```bash
python3 scripts/bible_checks/check_prereg_first.py \
  --repo /Volumes/CC/Enzyme_Agent/dependingv43 \
  --batch <批根目录>
```

校验四件事：预注册 md 存在、含判定线字段、approval package 哈希可核、
发车登记行存在。通过时末行 JSON `"status":"pass"`；缺任一件
`"status":"fail"` 且 findings 带路径；批根不可读时 `"status":"error"`
（退出码 2）。文档侧的手工自查用第 5 节清单。

## 7. 模板（预注册头骨架）

```markdown
# <批名> 预注册（<日期>）
- 题域标签：[298 域 / dev 域]，与其它题域双向不外推。
- 主口径 / headline：<criteria-vN，豁免开关状态>
- 分母：<固定 298；失败/unknown/空候选均不剔题>
- 判定线：达标 <区间>；未达 <回查线> 时强制回查（逐桶配对 diff）。
- 臂定义：A=<control>，B=<treatment>；两臂同值面：<模型/题集/判据/配置>。
- 停点：<阶段门阈值>；现场保护：stop.json 首写生效不删改；旧批 immutable。
- 发车登记：batch_tag=<...>；四文书 SHA=<...>；脚本锁=<...>。
- 签字状态：SIGNED / DRAFT_NOT_SIGNED（未签字不得发车）。
```
