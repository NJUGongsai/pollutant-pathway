# batch-discipline — 单变量成臂、同批对照

> 状态：L1 已完成（2026-10-26）。检查脚本已实现（`scripts/bible_checks/check_batch_discipline.py`）。

## 1. 一句话规则

一批只改一个变量并配同批对照臂；单修复单批测不出小增益，别拿噪声当效果。

## 2. 为什么

298 题 hit@1 的批间随机波动就有好几个百分点（历史各批 95% 置信
区间大面积重叠），一个不带同批对照的「修复批」，测出来的 ±2 题完全
可能是抽样噪声。chain13 四个变量叠一批，事后花了一整轮归因都拆不开；
这笔学费买来的纪律就是：要么单变量+对照臂，要么明说本批不可归因。

## 3. 细则

1. **同批同对照**：处理臂的效应只对「同批、同协议、只差目标变量」
   的对照臂成立；历史批数字只能当背景参照（如「T-H r2 是 89/298＝
   29.87%，是历史参照，不能充当新实验的同批对照」）。
2. **单变量**：模型、判据、供给、提示词、调用上限——一次只动一个；
   确要合并须在预注册写明「跨批不得称单变量归因」，并预留分族记账。
3. **方差基线**：新协议第一次跑建议双跑两臂（同协议只差采样）拿
   翻转率基线；后续单变量批用该基线判断效应是否超出噪声。
4. **小增益要靠推进线而不是肉眼**：净增几题算信号、几题算噪声，
   预注册里写死推进/止损线（如 B−O 净增 ≥5 题才进确认轮）。
5. **运营变量与科学变量分开**：传输失败重试、监控、smoke 阶梯这些
   运营件不影响单变量性，但要如实记录；科学口径面（prompt/判据/池）
   的任何改动都算新变量。
6. **跨批复制产物要保持身份**：两臂 build 一次复制 + 校验指纹可以，
   但 reference_graphs 等金标产物只在 HPC 批根之间复制、不入仓，
   复制来源与指纹进预注册。

## 4. 反例

反例：chain13 四变量叠加，归因拆不开
（`docs/C_COSUB_SUPPLY_REDESIGN_PREREG_2026-10-15.md:56`，事实链
`docs/CHAIN13_HIT50_DIAGNOSIS_GPT_2026-10-15.md:28`）
发生什么 → chain13 一批同时上 C 供给、声明链、criteria-v2 判据、
调用上限 1→3；预注册自己写明「一起变，跨批不得称单变量归因」。
→ 后果：掉分后要靠一整轮离线归因去拆「C 的净负贡献 vs 判据作用 vs
采样噪声」，且最终仍只能给观察账（C 组 v2 净零）给不出因果效应；
下一轮预注册直接写死「chain13 四变量叠加教训：不再多变量混批」。
→ 正确做法：变量拆批或同批分臂；合并批的报告里禁止出现
「X 导致 ±N 题」句式。

反例：T-H r2 单臂无 A/B，修复包效应与批次噪声不可分
（`docs/T_H_RESULT_2026-10-20.md:299`（限制表 #8），结论 `:23`）
发生什么 → T-H r2 预注册就是单臂；对 chain13 v2 净 +2 题、
对 chain14 A 反而 −2 题，落在历史单臂区间 85–91 之内。
→ 后果：报告只能写「不能宣称本修复包带来了高于批次噪声的工程
增益」，5 项修复面 0 项有候选级归因。
→ 正确做法：要验证修复包就配同批对照臂；只有历史批对照时，
结论降级为「落在噪声区间内」。

反例：置信区间大面积重叠——92 与 89 只差 3 题，分不出版本优劣
（`docs/REPLY_TO_TEACHER_HUANG_298_BEST_COMMIT_2026-10-22.md:76`）
发生什么 → bootstrap 95% CI：chain12 约 25.8–36.2%，chain14 A 约
25.2–36.2%，T-H 约 24.8–35.2%——高度重叠。
→ 后果：「最高 92」被明确标注不等于「最好版本」，不能据此建议
回退到 8da11cb。
→ 正确做法：凡跨批比较，先报区间再报点值；区间重叠时禁止下
「更好/更差」结论。

反例：两臂共享发车链时一臂故障连坐另一臂（运营面教训）
（`docs/FAST298_PIPELINE_2026-10-21.md:79`）
发生什么 → smoke10 一题撞 900 秒硬切触发一票否决，GLM 臂停的
同时已跑 46 分钟的 DeepSeek 臂被连坐 cancel。
→ 后果：一次网络抖动报废半天；该设计虽「按预注册」，但两臂耦合
停点使批次的实际方差远大于单臂设计。
→ 正确做法：臂间停点耦合写进预注册时就要报量化的停摆代价
（FAST298 后续按此改为探针放行 + full 容忍 ≤5 题）。

## 5. 检查清单

开工前：
- [ ] 本批变量清单：改什么、不改什么，逐项列出？
- [ ] 对照臂是什么（同批 A/B / 双跑方差基线 / 无对照→结论降级）？
- [ ] 推进线与止损线（净增几题进确认、几题关线）写死了吗？

发车前：
- [ ] 两臂同值面（模型/题集/判据/配置/prompt）逐项核对并锁 SHA？
- [ ] 臂间停点耦合方式与连坐代价已评估并落字？
- [ ] 跨批复制的产物来源与指纹登记了？

交付前：
- [ ] 对比表同口径（v1↔v1、v2↔v2，见 `dual-caliber`）？
- [ ] 效应结论带区间或换手分析（18 改善/16 退化这类），没用净差冒充单变量效应？
- [ ] 「本批不可归因」时结论降级声明在显眼位置？

## 6. 机器检查

脚本：`scripts/bible_checks/check_batch_discipline.py`（已实现，
契约见 `docs/BIBLE/_CONTRACT.md` §五）。

预期行为：给定批次报告 md，检查对比结论句是否满足以下之一：
①存在同批对照臂登记（batch_tag 对 + 差异变量声明）；②带置信区间
或逐题换手数；③含「不可归因/落在噪声区间」降级声明。三者皆无的
跨批效应句 → fail。手工阶段先查第 4 节清单第 2、4 条。

## 7. 模板（批次设计表头）

```markdown
| 项 | 值 |
|---|---|
| batch_tag | <...>（两臂同值） |
| 变量 | 本批唯一科学变量 = <...>；其余冻结面列表 <...> |
| 对照 | A=<control 臂>；B=<treatment 臂>；方差基线=<双跑翻转率或历史区间> |
| 推进/止损 | 净增 ≥<n> 题进确认；净增 ≤0 终止；strict 净失 ≤−3 停点 |
| 运营件 | 重试/监控/smoke 阶梯 = <描述>（不影响单变量性） |
```
