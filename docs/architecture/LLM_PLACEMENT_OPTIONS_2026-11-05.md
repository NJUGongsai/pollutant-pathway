## §0 结论先行

1. **问题不在"只调一次 LLM"，而在这一次被放在了失分最小的环节。** 现在 LLM 只负责"在候选池里挑顺序、顺便补几个池外提案"；而最大的失分在"池里根本没有正确答案"，这一层完全没有 LLM 参与。
2. **推荐把 LLM 挪到前面去，分三步：**
   - 先做"产物优先 + 程序核验 + 出错反馈"（O1 + O3），绝大部分零件仓里已有；
   - 再做"LLM 引导检索"（O2）；
   - 多采样（O4）等诊断证明排序噪声大时再上。
   - 多智能体分工和独立批评者（O5、O6）暂缓。
3. **判分始终零 LLM，这条不动。** 管线里加多少 LLM 都行，只要判分不碰 LLM，成绩就还算数。

## §3 选项说明

### O0 维持单次调用，只修输入（基线改良）

- **做什么：** 把第 1 轮评审指出的输入问题补上：让 LLM 看到候选的来源层级（是不是本底物的 recorded strict exact 记录）；解析失败时退回按池序排期，不再让整题报废。
- **改哪里：** `candidate_evidence.py`（来源字段）、`runflow.py`（结构失败兜底）。
- **针对哪类失分：** 排序损失的一部分。结构失败在本批只影响 [dev-298] 1 题、[biosysmodb121] 3 题。
- **成本：** 调用次数不变。
- **局限：** 救不了"答案不在池"。

### O1 产物优先 novel：LLM 直接写产物，程序反推原子映射来核验

- **做什么：** LLM 不再手写原子编辑，改为直接给出产物（可附共产物、共底物声明）。程序拿"底物 → 产物"做推断映射、编译、执行，核对执行出来的产物和 LLM 写的一致，一致才落事件。
- **现成零件：** `recorded_source.compile_recorded_reaction(substrate_smiles, donor_smiles, products, ...)`（`recorded_source.py:2886`）本来就是"已知底物和产物 → 推断映射 → 编译成可执行 spec"，供体填底物本身即可复用；产物多重集一致性门也已经在里面了。
- **针对哪类失分：**
  - 空池题：[biosysmodb121] 143 道；
  - 原子编辑写不出来的类型：B121 的 CoA 加合、磷酸化等，需要配合共底物声明。
- **成本：** 调用次数不变（仍是每题 1 次），工程量中等（主要是协议改动 + 接线）。
- **风险：**
  - **记忆污染：** LLM 可能"背出"训练数据里见过的 RHEA / BRENDA 反应。298 本来就是已见题，必须按来源分桶报告（P7），并且需要新题做硬留出。
  - **"声明、未执行"的共底物产物**需按任务书 P3 先预注册判分归属。
- **与判分的关系：** 不碰判分；事件仍须由程序执行得到。

### O2 LLM 引导检索：先让 LLM 读底物，再按它的判断去找候选

- **做什么：** 分两步走：
  1. 第一次调用：只给底物，不给池，让 LLM 列出"可能发生的反应类型 + 作用位点"（例如"芳环双加氧开环，位点 C3–C4""CoA 连接"）；
  2. 程序按这些位点和类型去检索，按反应中心匹配模板，而不是像现在这样只按整分子相似度召回（`services/analog_source.py:359` 是整分子 Morgan Tanimoto）。补进来的候选和原池合并，再进入现有的决策调用。
- **针对哪类失分：** 供给层（[biosysmodb121] 226、[dev-298] 98 no-CN）。另外先让 LLM 独立思考再看池，可以减少"有池就抄"的锚定效应。锚定效应是否存在，以 T1 的 C 块为准。
- **成本：** 每题 2 次调用；工程量较大，需要按反应中心或类型检索模板，模板库有没有可用的类型标注**尚未核实**。
- **风险：** 检索面变大以后，候选池截断（池宽 8）的规则要重新定；模板库里没有的类型照样补不上，这一块要靠 O1 兜底。
- **与判分的关系：** 不碰判分。

### O3 生成—核验—反馈循环

- **做什么：** 把格式反馈从 0 轮放开到 1–2 轮，而且反馈内容不只是 JSON 格式错误，还包括程序核验失败的具体原因：编辑预校验失败、执行失败、映射反推后产物对不上、元素账明显不平。LLM 据此改一版再提交。
- **现成零件：** 反馈轮的登记、计数、预算都已实现（`runflow.py:1257-1326`，`model_protocol.py`），只是策略设成了 0 轮。
- **针对哪类失分：** novel 提案的废品率（[dev-298] 本批"有调用零提交" 3 道；B121 空池题中 novel 失败的部分，规模以 T1 为准），和 O1 叠加效果最好。
- **成本：** 每题 1–3 次调用（只有失败时才追加）。
- **风险：** 反馈里**绝不能**带金标或判分信息，只能带程序核验结果，否则就等于用答案教模型。
- **与判分的关系：** 不碰判分。

### O4 多采样一致性（排序层）

- **做什么：** 同一题独立采样 k 次（例如 3 次），按确定性规则合并排序（例如按平均位次 / 投票）。
- **针对哪类失分：** 排序损失 [dev-298] 47、[biosysmodb121] 34 里属于抽样噪声的那部分。
- **成本：** 每题 k 次调用。
- **前提：** T2 核实采样温度，并做一次重复种子实验。如果噪声很小，O4 就没有价值。
- **与判分的关系：** 不碰判分。

### O5 独立批评者 / LLM 重排

- **做什么：** 第二个 LLM 角色审阅已执行出的候选事件，给出重排建议。
- **证据：** 旧嵌套 v44 仓的 RR 重排实验 hit@1 是 94 对 93 [dev-298]，几乎没动（口径未核）。
- **建议：** 暂缓。等 T1-E 的离线重排读数说明排序还有空间、而 O0 和 O4 都不够时再考虑。

### O6 多智能体分工（规划者 / 化学家 / 批评者）

- **建议：** 暂缓。它本质上是 O1–O5 的组合，额外带来的是编排复杂度和调试成本；在单个角色的收益还没被证明之前，上多智能体只会让归因更难。

## §5 推荐路线

```text
阶段 0（现在，零成本）: 任务书 T1 / T2 / T3 完成；O0 同步设计
阶段 1（第一批付费）  : O1 + O3 合并为一个实验臂（产物优先 + 核验反馈），在调参子集上与现行臂对照
阶段 2               : 视阶段 1 和 T1-B/C 读数决定 O2（引导检索）
阶段 3（有条件）     : T2 重复种子显示排序噪声大 → O4
暂缓                 : O5、O6
```

**为什么 O1 和 O3 先上：**
1. 零件现成，工程量最小；
2. 直接攻空池和"写不出来"两类失分，这是现在 LLM 能力被浪费得最明显的地方；
3. 不改检索，归因干净；
4. 调用次数增加有限。

## §8 风险与红线对照

| 风险 | 对应原则 / 措施 |
