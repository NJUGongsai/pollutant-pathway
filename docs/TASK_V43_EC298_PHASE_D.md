## 0. 目标、红线与顺序

目标是在**不放宽 Phase C 确定性门禁**的前提下，让结构相关且具有真实映射的供体进入评估，再用冻结 dev 20 的配对实验决定是否启用新策略、是否增加每父供体预算。最终看报告产物命中，不能仅以 applicable 数增加宣布成功。

按以下顺序实施：D0 冻结基线和实验协议；D1 实现按当前底物反应物相似度找回；D2 独立离线生成并审核映射资产 v2；D3 先做零 API 消融，再做真实模型配对实验，最后按本任务书预注册规则选配置。D1/D2 可以并行开发，但接线与全仓回归必须合并验证。

**红线：**金标只准在运行结束后的独立评分进程读取；不得用 EC298、Phase A 逐题归因或已见 66 条的正确答案选择相似度阈值、供体、映射或预算；不得从未映射区域猜编辑、对 `ambiguous` 任取一支、放宽氢/价态/电荷/键级/元素/AtomTool 目标对账和最终产物门禁；原始 rule/analog 检索卡不得绕过提案验证占报告位。若必须改变这些语义，应停下并另开设计审查。

## 1. D0：基线与数据隔离

1. 登记起点 commit、未提交改动、`configs/dev_batch.json`、prediction policy、prompt、冻结 v3 scorer、资产双清单和 Phase C 报告的 SHA。基线是 **Phase B+C 当前可复核代码、v1 类比资产、预算 3**，不是最初 EC298 首跑。先跑全仓无凭证回归及资产核验；故障基线不得进付费对照。
2. 保持接口分层：`AnalogSourceResolver` / `build_card_mapping_fields` 记录 donor refs 的找回来源，`build_eligibility` / `assess_donor` 判适用性，`classify_evidence` 落不可变资格块，`prediction_policy` / `run_identity` 冻结参数。`mapping_status=resolved` 不单独代表可迁移；Phase B `report_adjudication`、recorded 直通和 rank 限定可选集不因本阶段改变。
3. 冻结既有 dev 20 的 qid、输入 SHA、评分器 SHA、模型参数和配对口径。ReactionFinder、供体检索、LLM 任务、参数筛选进程均不得接收金标路径；金标 SHA 单独登记，由运行结束后的 scorer 使用。若 dev 20 曾被用于人工选择本次具体参数，逐项披露污染，不称该臂为独立验证。
4. 各实验臂使用独立 run 根目录，保存代码、资产、策略、检索算法、prompt、模型、输入清单和输出 SHA。身份变化拒绝旧 run resume；不能将旧 run 续跑成新配置结果。

## 2. D1：按反应物相似度找回供体

### 接口与语义

在 `services/analog_source.py` 增加供体**反应物**索引与 `templates_similar_to(substrate_smiles, *, threshold, top_k)` 等接口。索引键包含资产 SHA 和算法版本，防止跨版本缓存串用。去映射、标准化、立体处理、RDKit 指纹类型/半径/位数、Tanimoto、无效 SMILES 和阈值边界都需固定并写入策略。相似度只决定召回次序，绝不替代 `assess_donor`。

保留现有 `product_producing` 和 `corpus_trace` 通道，与 `reactant_similar` 合并。同一资产 SHA + 行号 + record_id 的供体只评估一次，保留全部 `find_channels`、每通道分数和原位次；不同记录不得因 SMILES 相同误合并。排序、去重及 tie-break 必须确定性，不能按金标或不同引擎的异构 score 排序。每条 ref 落 `asset_file`、`asset_sha256`、`line_no`、`record_id`、映射模板、通道和相似度版本/分数。无映射的 `corpus_trace` 仍只供溯源，不能因相似而变成 resolved。

新供体只属于**当前父节点、当前底物**的资格块，供体原始产物不得直接报告为当前底物产物。全部候选仍经 Phase C 变换提取、全对齐和化学门禁；不同目标继续 `ambiguous`。检索 top-K 与每父**实际评估数** `max_analogy_donor_candidates` 分别计数；未评估项标 `budget_not_assessed`，不得冒充 `inapplicable`。维持 Phase C 的 resolved 优先和稳定 tie-break，逐卡记录新通道是否挤掉原本会评估的供体。

### 参数冻结和验收

在任何 dev 评分前提交**不含 dev/298 金标**的参数卡：指纹定义、阈值、top-K、通道优先序、候选总上限、去重键、边界比较、资产无标签分布、性能成本及夹具依据。参数和版本进入 policy/run identity。不得在 dev 20 上遍历阈值后只报告赢家；若探索多个方案，先注册为独立实验臂并计成本。

无凭证测试至少覆盖：旧通道漏召回而新通道找回、阈值内/外/边界、无效 SMILES、双通道去重保双标签、同 SMILES 不同记录不误合并、resolved 不被低质项饥饿、找回但氢/价态不适用、两个转化竞争弃权、兄弟路径不串线。真实资产夹具核对 SHA 和行号。审计逐题区分**检索数、实际评估数、资格数、后续路由数**。

## 3. D2：映射资产 v2 与来源审核

1. 建独立**离线**管线，以 `assets/analog/corpus_templates_v1.jsonl` 为只读输入，用不看金标的结构条件识别部分映射。用有版本、配置和权重 SHA 的映射工具或可复核人工映射；只根据模板真实反应物和产物建立映射号，不从当前预测目标或 EC298 答案补造。工具不可用时标 `not_executed`；无审通过行时保留 v1 为运行资产。
2. 输出完整替代版 `assets/analog/corpus_templates_v2.jsonl`，v1 文件逐字节原样。每个 v1 record_id 在 v2 恰好一行；未通过重映射的行保留 v1 语义，不删除以制造较高通过率。交机器可读 provenance：原/新行号及行 SHA、record_id、原/新 mapped LHS/RHS、工具/版本/权重 SHA、状态 `unchanged|remapped|rejected`、理由和审核记录。拒绝行不能以新映射身份进入适用性评估。
3. 所有拟采用行机器检查：两侧可解析、映射号各侧唯一、保留原子元素一致、去映射的真实反应物/产物与原记录一致、反应变化非空、中心与变化一致、`extract_donor_transform` 可判定、`assess_donor` 不因坏映射抛异常。这些只证明结构必要条件。人工复核按固定种子分层抽样 `min(100, 拟采用行数)`，覆盖原子增删、芳香/立体、电荷变化等高风险层；机器门禁异常及抽中问题行全查。记录复核者、日期、抽样清单与结论；无人做化学复核则未过发布门槛。
4. v2 入 `assets/MANIFEST.sha256`、`assets/MANIFEST.json`，更新 `asset_manifest.py` 的版本化必需文件和装载选择；集合、字节数、哈希与磁盘双向一致。`assets/analog/MANIFEST.sha256` 若是旧资产历史清单，不就地改写；需要子清单则另建 v2 清单并纳入总清单。显式选择 v1/v2，v2 缺失不得静默退回 v1；所选 SHA 入卡、资格块和 run identity。旧 run 在资产变化时拒绝 resume。
5. 交 v1→v2 逐条差异与漏斗：候选、成功重映射、机器拒绝、人工拒绝、未改、实际从 unavailable 变可判定的数。测试覆盖部分映射→合法变化、重复映射号、原结构改变、工具结果无变化、无法映射、清单篡改及旧 run 身份拒绝。不得用已见 12 条恢复了多少“命中”作发布标准。

## 4. D3：离线消融和真实模型配对实验

### 4.1 零 API 分解

对同一冻结 dev 20 **输入**、不读金标，做四配置资格审计：C0（旧检索+v1+预算 3）、D1-only（新检索+v1+3）、D2-only（旧检索+v2+3）、D1+D2（新检索+v2+3）。逐题报新增/失去的 refs、通道、评估位置、`applicable/ambiguous/inapplicable/unavailable`、拒因、耗时和内存。D2 未过 §3 质量门时只跑 C0/D1-only，报告 `D2_not_released`。离线消融不是最终命中率，也不代表模型已修复。已见 Phase C 66 条只可作只读事后机制诊断，逐题标 `seen298_post_hoc_diagnostic`，不得据此调参。

### 4.2 真实模型 dev 20

D1/D2 质量门通过后，使用同一冻结 dev 20、`ZHIPU/GLM-5.3-Flash`、prompt、请求参数、路径预算、评分器和导出方式，运行以下独立臂：

| 臂 | 检索/资产 | 每父供体评估预算 | 用途 |
|---|---|---:|---|
| C0 | 旧检索 + v1 | 3 | 同版真实模型基线 |
| D-3 | D1 + 合格 v2 | 3 | 检索/资产联合效果 |
| D-5 | D1 + 合格 v2 | 5 | 预算增量 |
| D-10 | D1 + 合格 v2 | 10 | 预算增量 |

v2 未过质量门时，以 **D1+v1** 替代三条 D 臂，所有文件和表头明示，不写成 D1+D2。四臂各自最多 20 并行 worker，**不得同时启动成 80 个 API 并发**。在 Chenyu 上沿用 [接入文档](CHENYU_ACCESS.md) 的凭证注入方式；凭证只在远端 env/secret 中，不写入仓库、任务、日志或报告。每臂沿用 `configs/dev_batch.json` 的 30 元硬上限，四臂总上限 120 元；开跑前刷新并存档价格/配额快照，额度不足不启动。先做一题连通性/计费烟测，计入该臂账；超时、重试、孤儿调用全部计预算。限流时降低并发留痕，不绕费用门禁。中断/缺题的臂先按身份恢复或标实验未完成，不把部分题数与完整臂比较。

全部运行结束后由独立 scorer 使用同一冻结 v3 评分。交逐题 `cn` 与 `raw_sb` @1/@3/@5、首个报告位次、报告/提交产品数、类比/novel/recorded 来源、资格拒因、调用/重试/孤儿、token 和人民币成本。按 qid 配对列完成分母及赢/输/平；完整结果需 20/20，缺题不得暗补零分。dev 20 很小，报告原始计数和不确定性，不把 1 题波动称为可靠提升；适用率不能替代命中证据。

### 4.3 预注册发布规则

先判硬门：§2/§3 QA、全仓回归、恢复/身份、资产清单、费用账均通过；全部比较臂 20/20 完成且评分口径一致。任一不满足，结论 `no_release`，只交诊断。

硬门通过后，以 **`cn@1` 为主、`cn@5` 为保护指标**，其余指标完整报告。D-3 相对 C0 的配对 @1 净赢至少 2 题且 @5 不下降，才采用 D-3 的**实际资产/检索配置**（v2 合格时为 D1+D2，否则为 D1+v1）。若 @1 净赢为 0、@5 净赢至少 2，只可标“@5 改善候选”，**不得宣称 hit1 已修复或自动发布**。其余情况保留 C0。采用 D-3 后，D-5/D-10 只有相对已选最低预算臂继续满足 @1 净赢至少 2、@5 不降、费用未超限，才逐级升级；平局选低预算。不得用已见 EC298 的 budget10 诊断覆盖规则。报告所有未选臂及原因。

这些是小样本工程门槛，不代表统计显著性或环境机理证明。只完成离线消融而未完成真实 dev 对照，结论 `not_validated_for_release`，不得默认启用 v2 或将预算改为 5/10。

## 5. 接线、恢复和回归

1. 指纹/阈值/top-K/排序、通道版本、v1/v2 选择、供体预算及适用性版本进入 policy/run identity。不同配置用新 run ID，不兼容 resume 有端到端反例；D1/D2 落不可变检索卡/资格块，重放不得重新选择不同供体或改原卡字节。沿 record_id、asset SHA、evidence ID 可从答卷追到供体。
2. 对检索后、资格块写盘后、模型响应后、事件提交后分别做硬杀恢复：供体顺序、资格、LLM 调用/孤儿账、提案/事件、报告位次及导出 SHA 与无崩溃基线一致；不重复付费调用或提交。供体评估预算与 LLM/提案预算分别审计。
3. 保持 Phase C 防线：唯一 recorded 不入模型；rank 只选合格 recorded 任务候选，原始 rule/analog 无报告位；类比提案走 AtomTool 和最终门禁；竞争目标弃权。回归 rule/analog 双卡反例、竞争对齐、坏映射、无效元素、先增后引和兄弟路径隔离。
4. 新测试无凭证、无网络可运行；全仓测试零回退、资产双清单逐项通过。独立 reviewer 能重生离线产物并逐字节对账，付费臂能核对输入、账本与答卷 SHA。
