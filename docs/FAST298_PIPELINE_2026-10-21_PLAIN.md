# 298 题跑得更快更稳——大白话版（2026-10-21）

> 题域：298 = RHEA 通用酶学。这些数字只在 298 成立，不能套到 dev / HIT60 上。
> 完整版：`docs/FAST298_PIPELINE_2026-10-21.md`

## 一句话

慢不是机器不行，是**每题要让模型吐 2 万个字**；不稳不是 298 跑不动，是**三个小毛病把小抖动放大成整批停摆**。

## 现在什么情况

| 阶段 | 现在 | 说明 |
|---|---|---|
| 建题卷（build） | 61~64 分钟 | 全程只用 1 个核，给的 8 核一直闲着 |
| 跑题（run） | 3 小时 26 分~3 小时 40 分 | 8 路同时跑，已经跑满了 |
| 判分（score） | 3~4 分钟 | 不是瓶颈 |
| **一轮全程** | **约 6 小时** | |

## 为什么这么慢

每题模型要吐 **19,614 个字**，其中 **92.6% 是它自己想的推理过程**。一条流每秒只能吐 63 个字。

298 题 × 19.6k ÷ 63 = **92,300 个「流·秒」**。8 路除下来 = 3.2 小时，和实测完全对得上。

限流完全不是问题：现在每分钟才 1.44 次请求，上限是 200；每分钟 3.2 万 token，上限是 300 万。

## 为什么总报错

| 排名 | 毛病 | 有多严重 |
|---|---|---|
| 1 | 上游 900 秒硬切 | 39 次调用死在 899~900 秒；成功请求的 p99 已经是 858 秒，只剩 42 秒余量 |
| 2 | 10 题小门一票否决 | 1 题网络抖动 → 两臂全停；有一次另一臂已跑了 46 分钟被连坐 |
| 3 | 取消后留空目录 | 下次重试 100% 秒死，整个作业 40 秒失败 |
| 4 | 代理整段宕机 | 探针出现过 12 次里挂 11 次 |
| 5 | 重复提交 / 监控被回收 | 浪费一次发车、出问题看不见 |

429 限流一次都没有，节点挂掉、内存爆、超墙钟也是 0 次。

## 怎么改（先稳，再快）

**第一步：修 6 个稳定性毛病**（不改任何科学口径）
空目录自动识别续跑、删掉冒烟阶梯改 1 分钟探针、加 870 秒主动截断、发车前查重、监控脱离终端并写进度、备用出口探测。

**第二步：提速**

| 手段 | 效果 |
|---|---|
| 并发 8 → 40 | run 3.4 小时 → 42~48 分钟 |
| build 加多进程 | 63 分钟 → 9~11 分钟 |
| 同底物缓存（298 题只有 209 个底物） | build 再省 30% |
| 两臂只建一次、另一臂复制 | 每轮省 63 分钟 |
| 长题优先跑 | 再省 5~10 分钟 |

## 改完需要多久

| 阶段 | 时间 |
|---|---|
| build | 8~12 分钟 |
| run | 42~48 分钟 |
| score | 4~6 分钟 |
| **合计** | **55~62 分钟** |

你原来想要的 45 分钟，算下来需要 **52 路并发**才够。40 路更稳，所以这次按 55~60 分钟报。

## 两个必须知道的前提

1. **40 路从来没跑过**，历史上最多 8 路。上线前要先拿 40 题试跑一次，看单路速度还够不够 63 字/秒、900 秒断流率会不会涨。
2. **900 秒是谁切的没查清**，不是我们的代码（我们的超时是 60 秒只保单次连接）。要先按「870 秒自己放弃再重试」处理。

## 要登记的口径变更

`max_calls` 4470 → 6000、允许 ≤5 题失败仍出分、冒烟阶梯改成探针、两臂跨臂复制含金标产物。这四条都要写进预注册。
