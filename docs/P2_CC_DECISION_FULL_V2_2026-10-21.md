## 1. CC 原话

## 2. 口径澄清（避免把两件事混了）

- 冻结设计里的 **≤13% 是“输入 token 增量”设计护栏**，不是金额预算；它原本用于
  防证据卡把 prompt 撑大、保证实验可比与成本可控。
- 真实 298 池实测：批合计 **+8.2165%**（过），逐题 **104/298 超 13%**、最大 **+64.13%**。
- CC 明确不把 token 成本作为约束 ⇒ **不截断、不设逐题帽、不做 per-question exception**。

## 3. 决定

1. **P2 采用完整 v2 证据卡**（r2 patch `cd8c03e0…`，仅格式级紧凑分隔符；字段/语义完整）。
2. **C（逐题统一 13% 截断）不采用**；A K=1/K=2、B、D、E 修订方向一并关闭（不再作为 P2 主线）。
3. **token 增量改为披露项**，不再作为放行门：批合计 +8.2165%、逐题 104/298 超、最大 +64.13%
   必须随 P2 结果如实披露；真实批的实际 input/output tokens 照记，金额缺账单记 unknown。
4. **不因 token 成本砍实验、不因 token 成本改判据/池/排序/评分。**
5. 仍保留的其他 P2 门不变：T-I 模型选择、P2 独立预注册、v2 化学复审、付费批 CC/代决签字、
   真实批配对统计（全 298、新增/损失/净增、strict 净失 ≤−3 停点）。
6. 最终模型 tokenizer 下的 token 实测仍要做，但只用于**披露与实际用量核对**，不是放行门。

## 4. 影响

- P2 不再卡在 token 门；剩下的是**模型选择（T-I，当前被站点代理阻塞）→ P2 预注册 →
  化学复审 → 付费批签字**。
- 完整 v2 的 treatment 对 298 题一致，无截断/池序位置偏差，效果优先。
- 旧批、P0b、P1-B(A) 均不受影响；T-I 仍按 B2 等站点网络恢复。
