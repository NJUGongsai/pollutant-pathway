## 4. 为什么 B/E 类「无损压缩」被否（结构性算术）

104 题压到 13% 帽最低需削 **27,546 token（B 的 2.86%）**；整字段共享省 0.50%、
共享 participant 行省 0.95%、participant SMILES 无损引用化省 0.97%——**三项做满也只有
需削量的约三分之一**，且各自单独仍有 79–95 题超限。r2 紧凑分隔符已拿走约一半毛增量
（−74,584），剩余是真实内容成本（每候选 ~223 token，participants 一项占 42.4%）。
结论与上轮「格式级已到极限」一致并升级为：**字段级结构压缩也已到极限；过门只能删/截
证据内容（C）或改门阈值（判据变更，归 CC/老师，本代决不提议不预批）**。

## 5. C 的精确规则（设计冻结草案，须逐字进冻结文档与预注册）

- **R1 帽定义**：`cap_tokens(qid) = floor(tokens_v2A(qid) × 1.13)`。tokens_v2A = 该题
  v2 A 臂（同 v2 system prompt、无证据）首发固定载荷 system+user 两段 token 数，
  `add_special_tokens=false`，UTF-8 字节数不得当 token 数；tokenizer = **最终 T-I 模型
  tokenizer**（文件 SHA-256 登记），代理 tokenizer 读数只作先导。×1.13 系数与 floor
  取整逐字冻结；任何改动 = 判据变更，归 CC/老师。
- **R2 帽表**：最终 tokenizer 定版后离线计算 298 qid 帽表（qid → v2A_tokens、
  cap_tokens、tokenizer_sha、policy_version），写入冻结批 manifest 并登记 SHA-256；
  生产端只查表，不在热路径跑 tokenizer。若未来需对表外新题运行时计数，必须固定
  tokenizer 版本 + 确定性双跑测试 + 单独登记。
- **R3 截断触发与等级阶梯**：`payload_tokens ≤ cap` ⇒ 完整 v2 B（与冻结 v2 B 字节一致，
  零漂移）；`> cap` ⇒ **uniform 降级**：取使整题载荷（含 R4 披露键与题级
  substrate_evidence）≤ cap 的**最高**等级 ℓ，同题全部 prepared 候选同一等级。降级
  次序（先丢低优先级字段）：6 全量 → 5 丢 `product_delta` → 4 再丢
  `conditions_and_scope` → 3 再丢 `alignment_quality` → 2 再丢 `participants` →
  1 再丢 `functional_group_delta`（只剩 `edit_summary`）→ 0 候选证据对象整体缺席
  （题级底物卡永不丢）。阶梯顺序预注册后冻结；事后调序/调帽使本投影全部失效。
- **R4 披露键**：新增题级 `evidence_truncation`，至少含 `{policy_version, applied,
  cap_tokens, level, dropped_fields[], n_candidates, cap_table_ref(含 tokenizer_sha)}`；
  其 token 成本**计入帽检查之前**（实测读数已含）。截断字段**不得渲染为
  `unknown`**——截断是系统预算内主动省略，不是「系统不可得」，渲染成 unknown 与
  设计冻结 §一 的反造假条款冲突，属失实；prompt 证据段须如实定义 truncation 语义。
  披露键至少在截断题出现；若设计冻结选择全题出现（applied=false），必须同步复测
  194 个未截断题读数确认仍 ≤cap（本投影未覆盖该变体）。level-0 题由披露键可枚举。
- **R5 身份面**：schema 升版（candidate-evidence-3 → 4）、descriptor 升版（descr-3 →
  4）、prompt 证据段增补（v3 prompt 哈希登记）；run identity/resume 纳入帽表 SHA +
  policy_version；v1/off 路径逐字节零漂移（继承 r2 off_path_compare 口径，15/15 同款
  检查）。
- **R6 treatment 定义**：B 臂 = 「v2 证据卡 + 题级预算帽（uniform）」。**截断题仍属
  treatment 臂**，无逐题例外、不剔除、分母 298 不变；A 臂不变。预注册必须写明：
  token 门自此证明的是带上限卡的可负担性；完整 v2 卡效应只在未截断分层读。
- **R7 分层分析（预注册必备）**：总体 + 截断/未截断分层（代理口径 104/194；以最终
  tokenizer 帽表复测为准）+ 候选数分层（0/1/2/3/4/5+）；hit@1、strict、rank>1、
  novel 首选占比全分层报出；level-0 候选题留分母不入分子（与 novel 首选占比纪律
  同款）。strict 净失 ≤−3 停点**原样继承**（全局/任一分族，最高优先级不变）；截断层
  作为披露性分族，**新增停点属判据变更，归 CC**。
- **R8 不可行保护**：某题 level 0 仍 > cap ⇒ 硬失败：停并逐题报告，不得静默超帽或
  静默再删内容。代理口径 infeasible=0/298；最终 tokenizer 帽表必须复核并登记
  infeasible=0，非 0 时回 CC 裁定（不自动放宽）。
- **R9 确定性**：同输入 ⇒ 截断载荷字节一致（双跑测试）；候选集/池序/底物/执行图/
  判分零改动；等级选择 = 最高可行等级，禁止跨阶梯字段混搭。

2. **CC/老师拍板**：treatment 变更（截断=治疗的一部分）、token 门语义收窄
   （by construction）、帽表机制——字段面/判据类事项归 CC/老师，**本代决不代签**；
3. **mimo 场景 1 化学评审**：截断披露措辞（不得伪装 unknown）、丢
   participants/conditions/alignment 后证据卡的化学语义边界（如共底物方向信息的
   诚实呈现）是否触及化学判据；随设计冻结送审；
4. **实施轮 + Codex 正链实施审**：off 零漂移、帽表身份、确定性双跑、resume/identity、

5. **最终 tokenizer 全 298 复测**：v2 A/B + C 帽表 + 逐题增量 + infeasible=0 +
   截断题集与等级直方图登记（SHA）。

**最终 tokenizer + 全 298 复测不足以单独放行**：它只是门项。放行还需 §8 的独立
