## G1（CN 检索 + strict 编译核分层）

**结论：有条件同意——"检索宽、判分严"的骨架在化学上站得住，风险主要不在判分面而在报告语义面；需要三条防护句，不需要新增判据。**

### 机理展开

1. **CN 的实际碰撞面与请求里的担忧清单并不一致，先纠正再谈防护。** CN 身份 = RDKit Uncharger 电荷归一 + 立体盲 canonical（`domain/identity.py:27-55` 实读）。据此：
   - **互变异构体不会被 CN 合并**——Uncharger 不做酮-烯醇/酰胺-亚胺互变异构归一。所以"互变异构高发类假同"不是这里的主风险；它反而是**覆盖缺口**（互变异构写法不同的记录连 CN 都命不中）。请把报告里"CN 扩覆盖"的机理叙述限定为"质子化态 + 立体"两类，不提互变异构，否则是错误归因。
   - **盐式 vs 中性式大体也不合并**——Uncharger 不断开反离子，钠盐 `[Na+].[R-]COO-` 与游离酸的 canonical 仍不同组分/不同串。盐式命中主要是覆盖缺口而非碰撞。
   - **CN 真正的高频碰撞类是两个**：①质子化态差异（羧酸/羧酸根、胺/铵、酚/酚氧——化学上同一化合物，碰撞基本良性，这正是 +50/+42 的主体）；②**全部立体异构差异（R/S、E/Z、非对映体）**——其中**非对映体/差向异构体是化学上真正不同的物质**（不同熔点/极性/反应性，酶通常只认一个），这是"CN 同而化学上确属不同物质"里唯一值得写警示的高发类。
2. **分层实现核对：CN 永不升 strict 是代码事实，不是纸面承诺。** donor 严格身份==底物严格身份才授 `recorded_strict_exact`，CN 同而 strict 异一律 `recorded_cn_candidate`（`recorded_source.py:419-429` 实读）；且 CN 候选仍走同一编译+完整产物多重集 gate（`:430-437`），gate 用 strict 身份逐组分比较（`:547-575`）。质子化态/立体不同的记录，其"记录产物"的质子化/立体形态与在**本底物**上执行的产物几乎必然 strict 失配 ⇒ `product_set_mismatch` 诚实拒（`:564-575`；编译层另有 `charge_edit_unsupported`/`stereo_edit_unsupported`，`s5b_compiler.py:381-395`）。判分侧 `matched_strict` 的定义与 rank 序完全不消费 tier（`s5b_scoring.py:11-16`、`evaluation.py:1077-1080`）。**结论：CN 宽检索对 strict 判分尺子的直接化学风险近零，供给面增加的是 analog 级候选，不是 strict 命中。**
3. **一个请求没问但你必须知道的实现细节**：`cn_identity` 在电荷归一时若 `uncharge` 失败会**静默回退到纯立体盲比较**（`identity.py:52-55` 实读），此时带电差异也被抹掉——碰撞面比名义 CN 更宽，且发生率未披露。这需要计数披露。

## G2（组分级 donor 匹配 + 共底物声明）——本轮最重要的一条

**结论：有条件同意——方向正确（不冒充单底物反应是对的），但有一个必须在冻结前写死的 P1 级设计缺口：现行编译器结构上无法表达"产物组分来自未入 lhs 的共底物"，实现者被迫二选一：诚实拒（供给缩水）或把共底物原子伪装成执行期新增原子（化学误导）。条件不写死，这个设计不能冻结。**

### a) "条件/共底物参与物"声明是否语义诚实？

**部分诚实，术语必须拆开。** RHEA 净方程里"底物 A 之外的反应物"在酶学上是三类东西，混叫"条件参与物"会掩盖第一类：

1. **计量性共底物**（cosubstrate）：NAD(P)⁺/NAD(P)H、O₂/H₂O（单加氧酶）、ATP/ADP、CoA、谷胱甘肽、磷酸吡哆醛等——**按化学计量被消耗/再生**，是净反应的实打实反应物。请求 §7 自己的计数（NAD(P) 系 218、O₂ 114）说明这不是边角料。
2. **无机小平衡组分**：H⁺（179）、H₂O（134）、CO₂（47）——多数是书写侧的质子/水平衡项，"条件"一词对它们大致成立。
3. **真条件**（缓冲、温度、溶剂）——**根本不在方程里**，不该出现在任何参与物清单里。

把 1 叫"条件参与物"是化学误标：NAD⁺ 不是条件，是反应物。好消息是协议词汇表**已经有正确角色**：`PARTICIPANT_ROLE_COSUBSTRATE = "cosubstrate"`（`hypothesis.py:83` 实读）。规则文字应写死：**计量性共底物一律 `role=cosubstrate`、`side=reactant`；仅质子/水平衡组分可用"条件"措辞；真条件不得进入参与物清单。**

**相对参考边参与物集合比较，这些组分算什么角色？——答案是"参考侧未声明的事件侧多写组分"（event extras）。** 这不是角色问题，是覆盖轴问题：`match_reference_edges` 的 exact 要求 `reactants == from_states 且 products == to_states`（`evaluation.py:1062-1068` 实读），超集/子集一律进 `matched_participant_coverage_partial`（`:1065-1080`）。参考边系统性剥除无机/辅因子（r28 请求 P3 口径；参考图构建代码在金标侧，本轮未读，标未确认）——所以**事件侧诚实声明共底物 ⇒ 该边几乎必然 partial**。这是冻结判据 P1 的既定行为，不是冲突，但必须作为供给预期落字：见 c)。

### b) 产物侧完整性 + 共底物组合会不会产生"程序诚实但化学误导"的匹配？

**会。两个具体通道，请求自己点了一个，我补一个更隐蔽的：**

1. **请求点的 RL 反方向通道（成立，但风险可控）**：RHEA 双行只是同一平衡方程的两种书写（任务包 §4.2 "RL 行的书写方向=生化反方向"，`TASK_V43_PPV1_S5B_HIT50_V4_DRAFT_2026-10-10.md:171-176` 实读）。酶学上很多 RHEA 反应在体内强烈偏向一侧（连接酶、大量氧化还原反应的 ΔG 远离书写向）。把 RL 行直通迁移给底物，产出的是"该酶在热力学不利侧也会做出的净产物"——单步预测里这会把**需要能量耦联或体内反向进行的转化**呈报为可发生的单步转化。程序诚实（记录如此声明），化学上若被读成"该底物会主要变成这个"就是误导。**但判分侧不受污染**：匹配是侧别敏感的（`reactants & from_states` 且 `products & to_states`，`evaluation.py:1036-1040`），方向反的事件对不上正向参考边——误导面在**预测叙事与池槽占用**，不在分数字。缓解：方向来源逐候选披露（见 R2-3）。
2. **更隐蔽的通道——共底物产物拷贝进事件**：产物侧完整性要求"记录的全部产物都出现"。对 NAD⁺ 依赖的脱氢酶记录，完整产物集含 NADH。若 NADH 经"声明式"进事件，事件在化学上主张"A → P + NADH"——而参考边只声明 P。这在 P1 下是 partial（诚实、无害）；**但若 T1′ 忽略档被错误地宽用到辅因子（r28 已裁定辅因子不在任何忽略档、恒 partial，`mimo_ppv1_chem_review_response_r28.md:150` 第⑥条边界可类推），"A → P + NADH"就可能被洗成 strict**——那等于系统主张"脱氢酶反应不需要电子受体"。这不是本轮要裁定的事，但组分级供给上线后，这类事件会从边角料变成主力，**T1′ 的"白名单只含无机小分子、辅因子恒不忽略"边界必须在 v4 规则文字里显式引用一次**，防止实现时被"完整产物集语义"倒逼放宽。

### c) 共底物要不要在事件参与物里显式列出？——**要，且这是本轮唯一按 P1 级处理的条件**

代码事实链（全部实读）：

- 默认参与物装配：**反应物侧只有底物**（`production.py:217-222`），产物侧 = 主产物 + 全部 coproducts（`:223-232`）；协议支持显式 `participants` 覆盖（`:209-212`）。
- 判分：反应物侧多写共底物 ⇒ `reactants ⊋ from_states` ⇒ superset ⇒ partial（`evaluation.py:1062-1068`）。
- 判据二（冻结）：未知系数 ⇒ coverage/元素账/电荷账**记 unknown**，"两侧对称漏写参与物在本轴不可见"（冻结稿 `POLLUTANT_PATHWAY_CRITERIA_FROZEN_V1_2026-10-08.md:161-166` 实读）。

**推论（关键）**：如果设计选择"共底物只写条件字段、不进反应物侧参与物清单"来保 strict 通路，那么——事件的元素账**不会失败，只会 unknown**；判据二不会拦它。也就是说，**"把共底物藏进条件字段"这条路在现行冻结判据下没有任何化学守门拦得住**，而它对应的化学主张（底物单体 → 含共底物原子的产物）是元素不守恒的假单步反应。这就是"程序上诚实但化学上误导"的完整闭环。

**外加一个编译层的结构性发现（请实施方正视）**：现行编译器要求模板 lhs **完整落位**（"编译要求完整模板落位"，`s5b_compiler.py:286-297` 实读），且新增原子必须有已落位原子锚点、否则 `new_atom_unanchorable` 拒（`:594-599`）。组分级匹配若只拿匹配组分当 lhs 编译，记录产物里共底物来源的组分（NADH、乙酰-CoA 片段等）会落进 `new_union` 新原子通道——要么无锚被诚实拒，要么被强行锚在底物产物上，**产生原子"无中生有"的执行产物**。设计书必须写明共底物来源产物组分如何进事件（声明式拷贝 vs 执行式生成），以及产物多重集 gate 如何相应扩展（执行组分 ∪ 声明拷贝组分 == 记录产物集）——gate 扩展必须同源、落字、带负控，不能在工程轮静默改。

- R2-4（与 T1′ 的边界互引）："组分级供给上线后，coproduct_ignore_tier（若裁定非 T0）的既有边界——辅因子/有机共产物恒不忽略、白名单仅无机小分子——在 v4 规则文字中显式重申一次，防止完整产物集语义倒逼放宽。"

### "程序上诚实但化学上误导"风险点

- **风险 1（P1）**：条件字段藏共底物 + 元素账 unknown 被下游读成"已核平"——判据二的 unknown 语义（`:161-166`）在这里是弱点不是防线；必须靠 R2-2 的显式声明义务人工闭合。
- **风险 2**：共底物产物声明式拷贝后，事件呈现"A → P + NADH"这类**缺电子受体的假单步**；partial 桶是诚实的，但若后续有人以"partial 太多了"为由推动忽略档扩到辅因子，化学上是系统性倒退。R2-4 是疫苗。
- **风险 3（预期管理）**：+84 是**检索供给面**数字，不是 strict 可达数字；扣除"共底物含计量性有机物/辅因子"的记录后，strict 可达子集可能显著小于 84（占比未确认，缺逐记录共底物类型聚合计数——可做只读探针，不碰金标）。

**不确定项**：+84 中共底物仅为质子/水 vs 含 NAD(P)/ATP/CoA/有机物的分层占比——未确认；corpus 记录是否附 RHEA 方向性/生理方向元数据——未确认（资产在仓外身份块路径，本轮未读）；参考图剥除口径的构建代码——未确认（金标侧，按 r28 请求 P3 采信）。

## G3（RHEA 双方向行 + 通配原子行 + 推断映射守门）

**结论：三项处置全部有条件同意——双方向保留对（方向是声明且判分侧别敏感，不会双计分）；通配整体拒对（保守正确，仅需细分披露）；推断映射现有三道守门之外，我加两道必须的化学守门（记录自洽配平门 + 底物组分必须变化门）。**

### a) 双向行的方向语义陷阱

- **判分侧无陷阱**：如 G2-b 所述，匹配侧别敏感（`evaluation.py:1036-1040`），LR/RL 同 master 的两行对同一参考边只会命中其一；同净反应去重签名取全部产物组分的严格身份（`s5b_compiler.py:120-139`），两侧互换的行产生不同签名、不同槽——不会重复计分。
- **化学侧有真实陷阱，两个**：①"平衡书写向 ≠ 可发生向"（G2-b 通道 1，不重复）；②**池槽稀释**：对一个给定底物，只有 donor 侧（lhs）含它的那一行能编译，另一行大概率 `no_alignment` 诚实拒——无害但会把编译失败直方图灌水，直方图解读须注明"双向保留设计下的预期失败，非质量问题"。
- **落字建议**：R2-3（方向标注）+ "双向保留设计下，同 master 对另一方向行的 `no_alignment` 拒计数单列（类目 `opposite_direction_no_alignment`），不并入普通 no_alignment。"

### b) 通配行拒因类目化

- **整体拒是正确的保守选择，我不同意"按未指明共底物处理"的替代案。** 理由：通配 `*` 在 RHEA 语境是 R 基团类模板。若通配在**底物侧**，记录声明的是"一类化合物"的反应，拿单个成员去严格命中是**类模板冒充精确记录**——与 strict 身份口径正面冲突；若在**产物侧**，产物结构不完整，产物多重集 gate 无从谈起（记录产物自身不可 strict 识别）；若在**共底物侧**，同底物侧问题（共底物身份不完整，声明式拷贝也拷不出确定结构）。三种情形都触碰"不冒充可编译"的底线，整体拒 + 如实计数（任务包 §4.2 决策③口径）是对的。
- **但拒因直方图应细分**，为后续"类模板通道是否值得单独立项"留证据：按通配位置拆 `wildcard_in_substrate_component / wildcard_in_product_component / wildcard_in_coproduct_component` 三子类披露（工程级，零判据变化）。
- **落字建议**：R3-1："通配行按 `unsupported_wildcard_atom` 拒，直方图按通配位置三分子类披露；通配记录**不得**以'未指明共底物'名义进入任何供给通道；若未来立项类模板通道，属新供给面，须独立判据评审（新预注册），不得搭本轮车。"

### c) 推断映射的化学守门——在现有三道之外加两道

现有三道我全部认可且核过实现：产物多重集 gate 在**全部候选映射**上评估、择可复现者、等价合并、触顶/无可复现者拒（`recorded_source.py:541-575` 实读；r29-F2 的"选首非唯一性证明"落字也在）；枚举预算 200 匹配/512 删键调用、键差≤2（`:60`、`:74-77`）。另外 `transform_no_change` 会拒掉空变化记录（`s5b_compiler.py:253-258`）。**还缺两道便宜且高价值的门**：

- **G3-c-1（记录自洽配平门，加在字段适配层）**：RHEA 方程是人工审校的配平净反应。适配层回读记录后，对**记录自身**做元素账核：各组分分子式元素计数（全氢）反应物侧 == 产物侧（系数全为 1 时；含系数时按系数乘，corpus SMILES 若无系数则该记录标 `stoichiometry=unknown` 只披露不拒）。**任何不平 ⇒ 结构化拒（类目 `record_self_unbalanced`）**——不平意味着适配层组分拆分错误或来源数据缺陷，这种记录走推断映射+gate 的通过结果不可信。这是对接线层错误的廉价拦截，不是新判据（判据二管事件侧，本门管**源数据完整性**，与哈希审计同层）。
- **G3-c-2（底物组分必须变化门）**：推断映射的变化中心可能全部落在共底物/离去组分上（底物组分在记录里恒等）。这种候选的"转化"不是底物的转化——作为底物单步预测是误导。规则文字："记录的净变化原子集必须包含被匹配底物组分的原子；若底物组分在记录双侧恒等（变化全在其余组分），候选按 `substrate_identity_no_change` 拒，不入池。"（`transform_no_change` 只拦**整体**恒等，拦不住"底物恒等、共底物在变"，二者不同，需独立类目。）
- **落字建议**：R3-2（自洽配平门，含 unknown 系数的披露语义）、R3-3（底物变化门）。
- 另一条**建议级非必须**：映射 `useChirality=False`（`:213-215`、`:287-289`）意味着立体不参与对应枚举——这由产物多重集 gate 的 strict（含立体）比较兜底，立体保真记录若在保留中心发生描述符翻转会被 gate 诚实拒。行为闭环成立，不需要新门，但**规则文字可加一句**"推断映射立体盲，立体保真由产物 strict 多重集 gate 终核；立体差异记录的拒因计数单列"，防止读者把映射枚举数误读成"立体已核"。

### "程序上诚实但化学上误导"风险点

- **风险 1**：等价映射"选首"（`recorded_source.py:547-552`）在对称分子（同形双取代分裂产物）场景下，选哪条映射不改产物集但改中心原子归属；r29-F2 已落字"选首是工程事实非唯一性证明"，请确保 v4 交付书引用该句而非重新发明措辞——否则"中心已核"会被读过头。
- **风险 2**：`n_bond_diff`（键差 fallback 删键数，`:527`、`:587`）是诊断事实，**不是机制证据**（源码注释已如此声明，`:585-586`）；报告若把"2 条键差的对应"呈现为"该反应断了两条键"，就是把结构对应读成机理。落字："`n_bond_diff` 仅诊断，禁作断键数/机理陈述。"

## G4（总判定与冲突检查）

**一句话总判定：同意——v4 设计（CN 检索宽/strict 编译核严、组分级+共底物声明、双向保留+通配拒、推断映射沿用）与冻结判据一~五及 0d/0e 零冲突：分层不改 strict 身份（`strict_identity_of`/`cn_identity` 同源调用，`recorded_source.py:399-429`，符合判据五"strict 同源、旁证不叠加升格"），供给面扩展不改判分尺子（`evaluation.py:1062-1080` 与 `s5b_scoring.py:11-16` 本轮未触碰、语义零变化）；唯一 P1 级前置是 G2-c 的共底物声明义务与编译表达缺口，属设计冻结前必须补的文字条款，不是对冻结判据的冲突。**

逐条冲突检查（对照冻结稿实读）：

| 设计项 | 对照冻结判据 | 结论 |
|---|---|---|
| CN 检索 + strict 分层 | 判据一身份键（strict）；判据五"旁证不叠加升格"（冻结稿 :397-402） | 零冲突：CN 仅召回层，判分消费 strict |
| 组分级 + 共底物声明 | P1 集合语义（`evaluation.py:1062-1068`）；判据二 unknown 系数条款（冻结稿 :161-166） | 零冲突，但暴露 unknown=无守门的弱点（G2-c，P1 前置条款） |
| 双向保留 | 判分侧别敏感（`evaluation.py:1036-1040`） | 零冲突 |
| 通配拒 | 供给侧拒因类目，不进判分 | 零冲突 |
| 推断映射沿用 | 判据五"缺/歧义映射⇒中心 unknown，不猜"（冻结稿 :406-408）；触顶拒/歧义拒一致 | 零冲突 |

**最值得警惕的两个误判模式**：

1. **"供给面数字 = strict 收益"误读**：把 273（组分 CN）或 84（组分严格净增）直接外推成命中增量。化学上，这两个数字里分别混着"非对映体/质子化差记录"（本不该 strict）与"共底物含辅因子/有机物、现行 P1 下无 strict 通路的记录"（partial 命中不是命中）。这会重演"检索命中数冒充命中数"的老病，且这次披着严格口径的外衣更难识破。
2. **"完整产物集语义倒逼忽略档放宽"误读**：组分级供给上线后 partial 桶会显著膨胀（诚实后果），若下一轮以"partial 治理"为名把 coproduct_ignore_tier 白名单滑向辅因子/有机共产物，等于系统性主张"氧化还原/连接酶反应不需要共底物"——把判据的保守性当缺陷修掉。r28 已裁定的边界（仅无机小分子、产物侧差集、辅因子恒不忽略）是这条滑坡的止位钉，v4 文字须显式重申（R2-4）。
