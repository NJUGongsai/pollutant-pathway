## 3. R1-b：查清并修复 `pb_0117` 的 `TypeError`

1. 从 D-3 和 D-10 的 `pb_0117` 运行记录定位完整 traceback、抛错函数、输入和状态。不得只凭异常字符串猜测根因，也不得以 `except TypeError` 吞掉错误、补空值或强行导出掩盖问题。
2. 建最小确定性失败夹具，先证明旧行为会触发，再修复根因；验证两臂对应情形及其他正常输入。若触发条件涉及模型响应，夹具用封存的脱敏响应形状，不调用付费 API。

## 4. R1-c：批次完成、归并与配对评分门禁

1. 定义机器可读的路线状态：成功完成、合法停待预测/预算终止、异常失败、导出失败、缺失或未终止。`awaiting_prediction` 等**合法终态**可以产生空答卷，不等同于异常失败；`failed` 或 `export_ok=false` 即使有部分答卷也不能计为成功完成。每条路线应保留具体停因、导出 SHA、失败类别。
2. 批次报告不得在任一路线异常失败时无条件写 `status="completed"`。可设计 `completed | incomplete | failed` 等稳定状态，并给 `n_expected / n_valid_terminal / n_failed / n_export_failed / n_missing`、失败 route_id 列表；字段语义写入文档与测试。`merge_predictions` 可为文件形制输出固定行数，但元数据必须保留失败标志，不能把部分或补空答卷变成“有效完成”。
3. 配对评分入口以**冻结输入清单、每臂身份、批次终态、逐路线导出及 SHA**为准校验完整性，再读取答卷。`len(rows)==20` 或将来 `==298` 仅是行数检查。任一比较臂存在异常失败、缺题、重复题、导出失败、身份不一致或哈希不一致时，必须拒绝发布型配对结论；可以另生成显式标记 `diagnostic_incomplete` 的部分诊断，不得输出 `complete_20_of_20=true` 或可采用配置的判定。
4. 失败恢复要按既有身份/调用账本安全规则处理。允许修复后用**新批次身份与新 run 根**重测；若实现原批次 resume，必须证明不重发已提交调用、不覆盖不可变产物，且旧损坏 `decision` 不被静默放行。任务书不要求恢复旧 Phase D r1 四臂。
5. 失败夹具必须覆盖：20 行全在但其中 1 行 `failed` 且 `export_ok=true`；失败后部分答卷命中金标；失败后空答卷；合法 `awaiting_prediction` 空答卷；少/重 route_id；答卷 SHA 与元数据不一致；真正全部合法终态。断言不仅核对计数，还核对**发布判定被阻断或放行**。
