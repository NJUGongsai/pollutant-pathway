## 判断面二:自洽新内容不得占用旧地址(含"合法内容"变体)

**问 2①:绑定判据只看 (引用,身份) 二元组、不看载荷质量,是否过严?合法顶替是否该有通道?**

**1) 结论:同意,不过严。** 判据与载荷质量正交是本修复的**要点**而非缺陷:
旧地址承载的是"沿旧引用回溯历史"的入口,历史的属性是**曾被裁决**，不是
**内容合法**。案 4(checked 正规合法新内容占旧地址,tests:307-343)把这个
正交性钉成测试,方向正确〔待执行验证〕。化学类比成立且应写进规则文字:
科学记录体系里更正都是**追加式**的(audit trail,更正条目引用被更正条目),
从不原地覆盖——原地覆盖要么销毁旧裁决的依据,要么让已提交事件的历史判断
悬空。"合法内容就该允许顶替"没有正当场景;若有显式修订需求,通道应当是:
新 context_id+新地址+`parent_context_ref` 指向被修订上下文+显式修订记录
(带 source_ref,人/teacher 裁定),即"修订=加一条新记录并声明取代关系",
**不是**换绑旧地址。

**2) 可直接落进规则文字的修改建议**(两句):

- 「绑定判定只看 (请求引用, 恢复身份) 二元组,与载荷内容合法性、构造路径
  (直构/checked)无关;内容合法不构成占用旧地址的理由。」
- 「显式修订如需支持(本轮不实现,归用户/teacher):新 ID+新地址+
  parent_context_ref 指向被修订上下文+显式取代记录;静默顶替旧地址在
  任何情形下非法。」

**3) 风险点**:

- **"程序上诚实但化学上误导"点**:案 2/案 3 的突变载荷里,把 unknown 事实
  值改成实体值 `O2` 后载荷自洽——程序上这是一份"诚实的新记录",但它携带的
  化学断言("此处有氧受体")**从未经过该 run 的裁决链**。若守卫网传成
  "换 ID 就能继续",等于把无来源的化学断言洗进证据链。本轮守卫正是拦这个;
  规则文字建议点名:「旧引用回溯读到的新身份内容可能携带**未经本链裁决的
  化学断言**;拒绝的理由不只是工程一致性,更是化学断言的来源资格。」

**问 2②:零派生/零评估/零提交是否唯一正确处置?隔离坏上下文继续其他任务是否更优?**

**1) 结论:本会话 fail-stop 是保守正确的默认,同意;per-action 隔离是未来
工程选项,不是本轮缺陷。** 我核到的行为:`ConditionContractError` 是
RuntimeError(path_context.py:248),**不是** `PPV1RunError`/
`SearchContractError` 子类,故 `drive()` 的 run 级捕获(runflow.py:728-737)
**不吞它**——原样上抛,整个 resume 会话中止,endpoint 派生不达
(runflow.py:1667→1671 不执行),与 production.py:361-362 注释

**3) 风险点**:

## 判断面三:合法新内容新 ID 新地址 + parent_context_ref 链

**问 3①:新 ID 新地址+父链是否足以支撑审计回溯?**

**1) 结论:在已登记范围内,同意足以。** 我核到的可溯要素齐备:子上下文
`parent_context_ref=parent.context_id`(path_context.py:2404)且父身份进
子哈希(path_context.py:2417-2427)——链的每环把父身份焊进子身份,篡改
父引用会连环失配;逐要求带引入 phase/scenario/edge 绑定
(derive 内 `_bind_requirement`,path_context.py:2349-2357);转换快照带
`covered_requirement_signatures` 与 `source_ref`(path_context.py:
2385-2401),防空快照掩盖孤儿必要要求;事件/提交权威在账本行。历史裁决
沿链可溯,不需要内容顶替旧地址——判断面三的前提成立。

**2) 可直接落进规则文字的修改建议**(一句,补链路完整性边界):

- 「回溯链完整性以父 artifact 按其地址保全为前提;父 artifact 缺席/损坏时
  回溯结论为 partial/unknown 并机读披露断链位置,不得静默截断链或以子
  内容反推父内容。」

**3) 风险点**:

- 链是单向(子→父)指针:审计者要走链必须能按 `ctx:<id>` 取回每代载荷。
  保全是仓内既 standing 规则,但**规则文字里应显式**写出上面那句——否则
  "链在"容易被读成"链上每环内容已验证",而实际上每环都要在消费时各自过
  H07+身份+绑定三层(这正是把守卫放共同入口的红利,建议在规则里点明
  "逐环各过三层,不因链上其他环通过而豁免")。

**问 3②:"引用换新、历史冻结"组合在化学追溯上是否自洽?有没有必须原地覆盖的理由?**

**1) 结论:自洽,且原地覆盖在化学上是错误的,无此理由。** 条件相容性判断
本身是**条件依赖**的:旧边的评估只在旧场景/旧相位下成立,冻结侧 live 判定
含 scenario+phase、不拿新阶段事实重评旧边(path_context.py:2096-2102
docstring 原文)。场景转换后若原地覆盖旧边评估,等于用**新条件**重写
**旧条件下的实验结论**——化学上就是"换培养基后回头改写上一批培养的观察
记录",是数据造假形态而非修订形态。"引用换新、历史冻结"恰好复刻了科学
实践:新一批实验用新协议版本号,旧批记录原样留存,交叉引用。转换只后效、
不写成反应边、旧评估冻结于 phase_history(runflow.py:1315-1316 结果注记
与 derive 侧 path_context.py:2312-2314 一致),前后自洽。

**2) 可直接落进规则文字的修改建议**(一句):

- 「场景转换=开启新记录(新 ID 新地址),不是修订旧记录;旧边评估是
  **旧条件下的历史事实**,其有效性绑定旧 (scenario, phase),任何"以新
  条件重评旧边"或"原地覆盖旧边"的操作在本契约下非法。」

**3) 风险点**:

- **"程序上诚实但化学上误导"点(本轮最值得写进文字的一条)**:子上下文
  **继承**父事实拷贝(path_context.py:2407 条件事实 deepcopy 继承),
  程序上诚实;但读者若只看子上下文,可能把继承事实误读为"在新场景下**测得/
  断言**的事实"。事实的**来源场景**由其引入 phase/scenario 绑定承载,
  不随继承改写——建议规则文字明示「继承 ≠ 在新场景下重新断言;事实的
  条件归属以引入绑定为准,消费侧评估已按 scope 过滤(旧场景事实不评
  新场景要求)」,防止下游把继承读成再确认。
