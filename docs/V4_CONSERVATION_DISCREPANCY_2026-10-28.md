## 0. 一句话结论

**权威值 = 28/156**：v4 strict 156 题中，取**判分命中的那个事件**（rank 事件）、每个 participant
条目按写计一次、**元素 + 电荷同时守恒**的题数是 **28**；只看元素也是 **28**。

**分歧来源 = 事件选择 + 参与物去重**：Kimi 的 38 不是另一套化学判据，而是把
“**任一合格事件**守恒”（40 题）再叠加“同一 state_ref 参与物条目**去重**”（−2 题）得到的。
相对 Qwen 的 28：**多算 12 道**“rank 事件不守恒、但后面某个合格事件守恒”的题，
**少算 2 道**“rank 事件里同一物种写了两条、被去重后变不守恒”的题。
等式：**28 + 12 − 2 = 38**。

拆到两组更直观：

| 119 道 v2 保 strict | 14 守恒 | 26 守恒 | **+12**（任一事件） |
| 合计 156 | **28** | **38** | **+10** |

## 1. 两方口径还原

| 维度 | Qwen C2（28） | Kimi 扫描（38） |
|---|---|---|
| 题目集合 | v4 strict 156 | v4 strict 156（集合逐 qid 相同） |
| 取哪个事件 | 判分位次事件（`candidate_event_ids[rank−1]`） | **任一合格事件**（代码字段 `any_balanced`；其 `rank_event_balanced` = 26） |
| 参与物计数 | 每个 participant 条目按写计一次 | 按 `state_ref` 集合去重（同一 state 多条只计 1 条） |
| 守恒定义 | 元素差 = 0 且 电荷差 = 0 | 元素差 = 0（电荷剥离） |
| 解析错误 | 0 | 0 |

本复算做了三项独立核对，全部通过：

1. **集合**：strict 156 逐 qid 相同；119 kept + 37 flips 相同；与 `flips.json` 一致。
2. **位次**：rank 分布 `109/30/9/5/3` 与 Qwen 相同；156/156 的 `chosen_event_sha16`
   与 Qwen `chosen_event_id` 的 SHA256 前 16 位相同（即取的是同一个事件）。
3. **集合恒等**：本复算口径 b 的 28 道 = Qwen 的 28 道（逐 qid 相等）；
   本复算口径 d 的 38 道 = Kimi 的 38 道（逐 qid 相等）；
   本复算 d-rank 的 26 道 = Kimi `aggregate.json` 的 `rank_event_balanced` 26 道。

**Kimi 的 38 是怎么来的**：其扫描脚本对每题统计所有“合格事件”，只要**有一个**事件元素守恒，
就把该题记为 `any_balanced=true`；报告 §0/§2 直接用了 `any_balanced` 的总数 38。
同一个 `aggregate.json` 里 `rank_event_balanced` 只有 **26**。38 与 26 的差（12 题）
全部来自“非判分位次的合格事件”；这 12 题全部落在 119 道 v2 保 strict 组。

**Kimi 的去重细节**：其脚本把 `react_ids` / `prod_ids` 建成 `set`，再用
`[ident[sid] for sid in react_ids]` 取物种，因此同一 `state_ref` 的多条 participant 条目
会被折叠成一条。rank 事件里出现重复条目的共 4 题（均在 37 翻转集），影响如下：

| qid 前缀 | 重复条目 | 按写逐条 | 去重后 | 影响 |
|---|---|---|---|---|
| `RXNG_654cc…` | 反应物侧同一水条目 ×2 | 守恒 | H:−2,O:−1 | 28→26 的 −1 |
| `RXNG_fc908…` | 反应物侧同一水条目 ×2 | 守恒 | H:−2,O:−1 | 28→26 的 −1 |
| `RXNG_37e263…` | 产物侧同一 HCl 条目 ×2 | H:−2,O:−1 | Cl:+1,H:−1,O:−1 | 只改分桶 |
| `RXNG_66271…` | 产物侧同一水条目 ×2 | H:−6 | H:−4,O:+1 | 只改分桶 |

全批最大系数 = 1.0，参与者系数只有 `1(known)` 与 `None(unknown)` 两种；重复条目就是
“写了两份”，按写逐条计数才复现事件本身。去重不是化学判据差异，是实现细节。

## 4. 推荐口径与理由

**推荐 b：rank 事件、逐条计参与物、元素 + 电荷同时守恒；权威值 28。**

1. **“v4 strict 题”的身份由判分位次事件定义**。hit@1 = 109 也是按这个位次算的；
   换成“任一合格事件”会让披露口径与 strict/hit@1 脱节。12 道 any-only 题正是
   “模型写了后续完整事件、但判分位次上不是它”的情况，不能算作“按写配平”。
2. **逐条计参与物是“按写”的字面要求**。同一 state_ref 写两条（两份水 / 两份 HCl）
   就是写了两份；系数全批最大 1.0，没有缩放歧义。去重会改变反应式本身。
3. **元素差是“补给缺口”的主信号**。H:+2（缺氢受体）、O:−1（缺氧源）、H:−2,O:−1（缺水）
   三类共 109/128，直接对应参考声明“只写底物 + 主产物”的系统性缺口。
4. **电荷项在本批不改变 headline**（a = b = 28），但它是配平的标准定义；保留电荷项
   可以把 3 道电荷异常单独披露，成本为零。
5. **不建议 c 作 headline**：c = 30 会把 2 道“反应物侧多写一个 H⁺”的事件算成守恒，
   掩盖了按写方程的电荷错误；H⁺ 在介质中可自由获得，不等于写错边也无所谓。
   c 可以作为敏感性一行（30）。

对预注册/对外披露的建议写法：

- 主张数字：**strict 156，其中按写元素+电荷守恒 28（17.9%）**；元素-only 同为 28。
- 同时披露：128 不守恒；主类 H:+2 50、O:−1 35、H:−2,O:−1 24；电荷差 3 题
  （2 题反应物侧多 H⁺、1 题产物侧多硝酸根）；12 题 rank 事件缺氢受体但存在后续守恒事件；
  4 题 rank 事件含重复参与物条目。
- **不把 38 或 40 写成“按写配平”**；若引用 Kimi 的 38，必须注明
  “任一合格事件、元素口径、按 state_ref 去重”，且它不是判分位次口径。

**结论：不是“两边各对一半”。** 28 是唯一与判分事件一致、且可被两套独立实现同时复现的值
（Qwen 的 C2 与本复算逐题集合相同）；38 是 Kimi 扫描脚本 `any_balanced` 字段的口径，
加上 `state_ref` 去重实现细节造成的，不能作为“v4 strict 按写配平题数”。Kimi 报告 §0
与其自身 `aggregate.json` 的 `rank_event_balanced=26` 也不一致；引用时以本复核为准。

**下游影响（守恒作门的推算）**：Kimi 回复文档把 38 用作“守恒若作判对门：156→38、
v2 已判对 119→26”的论据。按本复核，判分事件口径下应是 **156→28、119→14**；
放宽到“任一合格事件”才是 40/26。结论方向（守恒不能作门）不变，而且更不利于“作门”；
但门槛上的数字应按 28/14 引用，不能按 38/26。
