# dual-caliber — 口径变更走新版本、双口径并列、历史不覆写

> 状态：L1 已完成（2026-10-26）。检查脚本已实现（`scripts/bible_checks/check_dual_caliber.py`）。

## 1. 一句话规则

判据/口径变更开新版本号重判，新旧口径并列披露；历史数字与原文永不覆写。

## 2. 为什么

「换尺」本身就会改变排序结论（仓里实测：主口径与老口径对同一批的
方向都不一致）。如果允许拿新口径悄悄覆盖旧数字、或拿新尺比旧尺，
那么任何「进步」都可能是量尺的 artifact。双口径并列 + 历史不覆写，
让每一次换尺都留下可审计的对照。

## 3. 细则

1. **新口径 = 新版本号 + 全量重算 + 披露件**：criteria-v1→v2→v3 各自
   有版本号、豁免开关定义、与批内全部产物重算；v3 是纯披露轴时必须
   写明 `strict_promotion=false、hit_at_1_effect=none`。
2. **跨批比较只用同口径表**：v1↔v1、v2↔v2 各一张表；headline 口径
   在报告开头声明，且每张表旁标注口径。
3. **换尺效应单独入账**：同批 v1→v2 的差值是「测量修正」（如 +5，
   跨批稳定复现的 H2O 豁免效应），不是工程回收；对外引用时要分账。
4. **不同尺的数字禁止换算或直接比**：老口径 anyof 与主口径的命中
   对象、K 槽含义都不同，差额不构成「还差 N 题」。
5. **历史件不改写**：口径更正后，旧文档里的旧标签以新字典为准引用，
   原文不回写（P3 O0 明文「原文不作回写」）；被新 SHA 取代的旧文书
   作为历史件保留。
6. **对外必须双口径并列**：主口径与敏感性口径（如老口径）方向不一致
   时，不能只挑好看的那个发。

## 4. 反例

反例：拿 v2 的 87 去和 v1 的 84 比——任务书里的口径混用
（`docs/T_H_RESULT_2026-10-20.md:97`）
发生什么 → 任务书写「chain13=87」，那是 v2 口径；T-H 的 v1 是 84。
若直接对比会凭空多出 3 题的「退化」。
→ 后果：报告专门列「口径标注（必须随表读）」节：chain13 根
metrics.json 是 v2 headline=87、`.v1` 文件是 83，四批口径逐字对齐后
才做差值表。
→ 正确做法：每个数字引用时带口径版本；对比表分 v1↔v1、v2↔v2。

反例：anyof 145 被读成「离 149 只差 4」
（`docs/CHAIN13_HIT50_DIAGNOSIS_GPT_2026-10-15.md:82`）
发生什么 → 老口径（产物字符串 anyof）GLM=145，与目标 149 差 4；
但主口径核的是根事件严格匹配，二者命中对象与 K 槽含义都不同。
→ 后果：报告明写「差额不代表可以通过调尺子合法兑换」——不能拿
宽口径数字冒充主口径的进度。
→ 正确做法：不同尺各报各的，禁止跨尺做减法。

反例：v1→v2 的 +5 是测量修正，差点被记成工程收益
（`docs/T_H_RESULT_2026-10-20.md:24`，分账表 `:274`）
发生什么 → 同一批 v1 84 → v2 89 的 +5 全部来自 criteria-v2 的 H2O
豁免口径，5 题全是 partial→strict→rank1，且其中 4 题在 chain13、
chain14 A/B 同样翻转——是跨批稳定的口径效应。
→ 后果：报告把「测量修正 +5」与「工程回收 +2」分成两行记账，
41.79% 这类转化率也注明「不能把 v1→v2 的增益全算成工程收益」。
→ 正确做法：换尺前后的差值永远标「测量修正」，与干预效应分账。

反例：口径更正后历史原文不回写，改引用方式
（`docs/T_H_P3_O0_METRIC_RECONCILIATION_2026-10-23.md:319`，另一例
`docs/HANDOFF_MAIN_TO_P2_2026-10-21.md:64`）
发生什么 → P0 摘要/决议包里「F3 992 条」「recorded/corpus 等 178」
等旧标签被 O0 对账证伪；P2 旧 qwen 确认报告引用已被取代的旧 SHA。
→ 后果：两处都选择「以新字典为准更正引用方式，原文不作回写」/
「作为历史件不改写」——旧件保持原样作为历史快照，新件挂指针。
→ 正确做法：勘误走新文档 + 指针，不涂改历史；引用旧件时带勘误注。

## 5. 检查清单

开工前：
- [ ] 本轮是否改判据/口径？改 → 走新版本号 + 预注册，不开隐藏开关。
- [ ] 新口径的定义（豁免集合、strict 判定、分母）写成机读披露件了吗？

发车前：
- [ ] 报告 headline 口径声明落字？
- [ ] 历史批对照数字各带口径标签（v1/v2/v3、主口径/老口径）？

交付前：
- [ ] 对比表同口径分组，无跨口径行？
- [ ] 测量修正与工程效应分账？
- [ ] 新旧口径并列披露，未只挑有利口径？
- [ ] 勘误只加不改：历史文件未动，新件带指针与依据？

  strict_promotion=false、hit_at_1_effect=none>。

- 跨批表：v1↔v1、v2↔v2 各一张；分母均 <N>。
- 换尺效应单独记账：<批内 v1→v2 差值 = 测量修正，非工程回收>。
