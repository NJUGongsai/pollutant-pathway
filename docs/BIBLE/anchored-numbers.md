# anchored-numbers — 一切数字带锚

> 状态：L1 已完成（2026-10-26）。检查脚本第一批已实现。

## 1. 一句话规则

每个数字写清 commit、口径、批次/出处三锚之一缺一不可；单位与分母随数字走。

## 2. 为什么

裸数字会在转述中漂移：一个没带锚的「30.5%」可以被安到任何一个
commit 头上，一个没带单位的「992」可以从计数器变成「F3 条数」再
进决议包。等发现时，错误数字已经扩散进多份文档，回收成本远大于
当初多写半行锚的成本。锚不是格式洁癖，是数字的可回收性。

## 3. 细则

1. **成绩数字三锚齐全**：跑分代码 commit（7 位以上短哈希）+ 判分
   口径（criteria-vN/主口径/老口径）+ 批次（batch_tag 或 metrics 件）；
   比例写成分数形式（89/298 = 29.87%）而不裸百分比。
2. **计数带单位与分母名**：题/候选行/已调度 spec/事件/计数器/报告
   是不同单位；234/242/151 这种「长得像」的数必须带分母名
   （已调度 spec / P2 spec 面 / P2 题面）。
3. **计数器不得当条数引用**：`analog_pregate_skipped`（992）这类
   counter 只能以全名+计数器身份引用，并注明重叠关系（与 864 重叠
   814，禁止相加）。
4. **证据分级随数走**：D0（冻结 JSON）> D1（易失副本重算，须注明
   出处与「副本已失」）> derived（闭合等式推出）；拿 D1 冒充冻结
   证据是明确禁止项。
5. **模拟/投影/他仓数字必须标性质**：模拟投影（95/298）、他仓成绩
   （hpc2-A 94/298 在 v44 仓）、目标值（149/298）都不是实测成绩，
   引用时逐一标明。
6. **题目域标签**：298 域与 dev 域双向不外推；对外数字必须带题域
   标签（AGENTS.md 红线）。

## 4. 反例

反例：构想方案自己第一处数字就没带锚，且锚内部矛盾
（`docs/PROPOSAL_SELF_ITERATING_AGENT_BIBLE_2026-10-22.md:18`；
该文 `:36` 自己要求「一切数字带锚」）
发生什么 → 方案基线表写「ppv1 当前架构（chain14 A / c9c6c7a，
30.5%）」。对照权威核查件：chain14 A 的跑分 commit 是 `3440ca7`、
成绩 91/298 = 30.54%（v2）；`c9c6c7a` 是 `origin/v4.3` 分支头、
成绩 89/298 = 29.87%（`docs/REPLY_TO_TEACHER_HUANG_298_BEST_COMMIT_2026-10-22.md:64`、
`:148`）。
→ 后果：「c9c6c7a + 30.5%」这对锚互相打架——30.5% 属于 3440ca7
的 chain14 A，不属于分支头；且 30.5% 没带分母与口径。写方案的同
一天仓里已有权威核查件，几秒钟可查。
→ 正确做法：写成「chain14 A（`3440ca7`，91/298 = 30.54%，criteria-v2），
分支头 `c9c6c7a` 为 89/298」；一份文档内的锚必须互相咬合。

反例：992 从计数器漂移成「F3 条数」并进决议包
（`docs/T_H_P3_O0_METRIC_RECONCILIATION_2026-10-23.md:18`（更正表）、
`:284`（禁止相加清单））
发生什么 → P0 摘要/决议包把 992 写成「F3 992 条」「F3 wildcard 预门
跳过 992」；实际 F3 wildcard = 178 条候选行/52 题，992 是
`analog_pregate_skipped` 计数器 = 178+407+407，与 F5 reject 864
重叠 814。
→ 后果：需要一整轮 O0 对账（51 条指标字典 + 闭合等式复验）来回收；
「864+992 会把 814 数两遍」被列为头号禁止项。
→ 正确做法：计数器以全名引用并注明单位 counter；相加前验互斥。

反例：三个长得一样的 remap 数字分母不同，混写即错
（`docs/T_H_P3_O0_METRIC_RECONCILIATION_2026-10-23.md:99`–`:105`，
禁止互换 `:291`）
发生什么 → 234（已调度 analog spec）、242（P2 spec 面）、151（P2
题面）三个 remap 数字被互换使用；134 被写成「remap 欠账」，实际是
「未触发 transform_no_change 的补集」。
→ 后果：O0 把三个分母列成对照表，规定「remap 三数必须带分母名」。
→ 正确做法：数字+分母名+单位三者同句出现。

反例：模拟投影与他仓数字混进成绩表
（`docs/REPLY_TO_TEACHER_HUANG_298_BEST_COMMIT_2026-10-22.md:105`、
`:102`）
发生什么 → 「95/298」是提交 `48e756e` 里的模拟投影；「hpc2-A
94/298」在 v44 仓（RetroRules 供给线），不在 v4.3 分支——都出现过
在文档里，容易被当成 v4.3 实测成绩引用。
→ 后果：核查件专设「容易混进来的几个数字」节逐个排除，明确
「同线、同口径、同 298 分母」才进成绩表。
→ 正确做法：数字入表前过三问：哪个仓？实测还是投影？哪把尺？

## 5. 检查清单

开工前：
- [ ] 本轮要引用的历史数字，锚（commit/口径/批次）都从权威件抄了吗？
- [ ] 单位与分母名定了（题/行/spec/事件/counter）？

发车前：
- [ ] 预注册里的目标线写成分数形式并带口径？
- [ ] 跨仓/跨线数字已标隔离声明（如 hpc2 在 v44）？

交付前：
- [ ] 每个百分比有分数形式与分母？
- [ ] 每个 commit 引用 7 位以上短哈希且与登记件一致？
- [ ] D1/derived 数字带证据级标签？
- [ ] 模拟投影、目标值、他仓数字标了性质？
- [ ] 没有把计数器写进任何加法？

## 6. 机器检查

脚本：`scripts/bible_checks/check_anchored_numbers.py`（第一批已实现）。

```bash
python3 scripts/bible_checks/check_anchored_numbers.py \
  --repo /Volumes/CC/Enzyme_Agent/dependingv43 \
  --files 'docs/Your_Report_*.md'
```

扫指定 md（默认 `git diff --name-only HEAD` 中的新增 md）：形如
`NN.N%` 或 `NNN/298` 的数字，同一行或相邻 2 行内须有 commit
（7–40 位 hex）、口径标签（v1/v2/v3/dev/298）、批次名三者之一；
无锚 → fail，每条 finding 带行号与数字。注意：本文件第 1 节规则句
与模板示例中的数字属规则陈述，检查器如误报可把规则句放入豁免清单
（降误报的参数化方案：`--exempt-regex`）。

## 7. 模板（成绩引用行）

```markdown

  证据级 D0/D1/derived）。
- 对照：历史最高 <N'>/<分母>（`<commit'>`，<口径'>）；差 <±n> 题，
  置信区间 <…>，<能否区分优劣一句话>。
```
