### R1 装配的重复次数与 copy 引用不得被“同结构出现过”替代

**文件：** `production.py:1664–1670,1688–1696,1784–1793`；新增测试文件；修订合同／交付说明。

**独立行为：** novel 声明两份相同 coproduct，而事件产物侧只有一份时，公开派生仍返回 `consistent`，`declared_generated_present=3` 而 `event_product_components=2`。原因是逐条做包含，每次重复使用同一份组分；展示计数也用 `k in assembly_keys` 重复计入。这违反合同 §1.2／§1.4 的多重集（保留重复次数），不是要求新增配平或机制证明。

另一个最小合成载荷中，copy 声明的 `state_ref` 不在事件，只有同结构的另一个引用，公开派生仍给 `copy.in_event_products=true` 和 `consistent`；源于 `:1667` 的引用条件与结构条件以 OR 相连，违反合同 §1.5(1)。**限度：**正常 strict 状态 ID 由结构身份确定，既有 prepare 又检查 copy 引用；本轮未证明这种异 ref 输入能从合法 production 提交产生，未发现 admission 绕过或真实历史污染。这是新派生 API 的直接合同偏差，应在本轮同处局部修正，不升级为另一项生产安全工程。

**具体改法：**装配轴使用共同的多重集比较／交集计数，不能让同一出现无限复用；copy 的“被引用”严格检查声明 `state_ref`，结构对应作为另一披露轴，不代替引用。按既有参与物出现口径处理，不在本轮引入新的系数／配平判据。新增重复 coproduct 缺一份的负控、重复份数齐全的正控、合法 copy 正控及 copy 引用缺失负控，并在 reconcile 与公开 derive 两层覆盖。

**必须重跑：**新增同根正负控、原 C1/C2、公共 off/on→export 集成、既有相关测试／T11，以及修后正式 Phase D 与 crosswalk；保持候选／评分零漂移，不要求旧诊断分布硬凑原数。

### R2 缺少装配资料时保留 unknown

**文件：** `native_result.py:585–593,671–699`、`production.py:1481–1492,1574–1593`；新增测试文件及合同 §1.7／§1.9／§1.10 对应说明。

**独立行为：**保留可比较的 principal、执行及 novel coproduct，删除事件 `participants` 字段，公开派生返回 `inconsistent / declared_coproduct_missing_from_event`，`unknown_reasons=[]`、`unverified_ranges=[]`。同一底层 reconcile 若收到 `None` 可以正确给 `event_assembly_unavailable`；聚合入口先用 `body.get("participants") or []` 把“未提供”变成“已知为空”，丢掉了必要 unknown。对应合同 §1.10 的既有枚举和 §1.8 的未核范围要求。

同根的合同完整性反例：事件缺少 production report 时，公开 derive 也无法通过 report 的 action_id 取得 spec，最终因全空提前返回 `not_applicable`，未知原因及未核范围均空。这**符合现合同 §1.7 字面，不是被洗成 consistent**；但合同未区分来源缺失与已核空声明，导致聚合入口的 `missing_production_report` 失去作用。此处需同时澄清合同，而不能只称实现违约。已知空声明的合法 `not_applicable` 正控必须保留。

**具体改法：**让缺失／非对象事件载荷、缺失／不可用参与物等资料缺口传到共用核验源，不能在聚合入口归一成合法空列表；保留“参与物资料完整且明确为空”的不同语义。需要装配核验但资料不可用时输出 `unknown / event_assembly_unavailable`，并写入 `proof_scope.unverified_ranges`。来源缺失时先保全 `missing_production_report`／`missing_spec`，只有声明与执行确知为空才走 `not_applicable`。不要为了修这一项把所有装配异常一律改 unknown。

**必须重跑：**公开 derive 与 reconcile 的“报告缺失、spec 缺失、资料缺失／坏类型、已知空声明、明确空参与物、合法完整、确有矛盾、解析失败”矩阵；保留 C5/C6/C7；再跑公共集成及正式零漂移门。不能只修 helper 而不测聚合消费入口。
