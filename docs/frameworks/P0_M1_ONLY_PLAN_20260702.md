# P0 M1-Only Forward Plan

Date: 2026-07-02
Status: PROPOSED — pending teacher sign-off
Supersedes: `concat_pooled_vec` as default downstream feature
Target repo path: `docs/reference_plans/P0_M1_ONLY_PLAN_20260702.md`

## 1. Decision

Drop `concat_pooled_vec` (512-d) and `seq_pooled_vec` (M2, 1024-d) as downstream
training features. Use **`embedding_pooled_vec` (M1, ESM2-3B pooled, 2560-d)**
as the sole sequence-derived enzyme feature for P1 training.

Rationale (from `P0_STEP6_LUCA_CONCAT_DIAGNOSTICS`):

```
concat_pooled_vec : effective_rank = 2.45 / 512   (collapsed)
                   pairwise_cosine_mean = 0.959
                   top1 eigenvalue = 11.9 (dominant)

M1 embedding_pooled_vec : effective_rank = 691.8 / 2560   (healthy)
                          pairwise_cosine_mean = 0.711
                          multi-direction singular spectrum

M2 seq_pooled_vec : effective_rank = 3.0 / 1024   (degenerate)
                    pairwise_cosine_mean ≈ 1.0
                    covariance eigenvalues ~1e-10
```

Root cause: M2 is the LucaPCycle sequence/BPE Transformer branch trained for the
phosphorus-cycle 31-class recognition task. On our enzyme dataset it collapses
to a near-constant vector. Because `concat_pooled_vec` is the model-internal
fused M1+M2 representation (the final classifier input), the degenerate M2
contaminates the fusion and collapses `concat` to ~2-3 effective directions.

M1 uses ESM2-3B, a general protein language model, and retains diversity on our
enzyme set. It is the only healthy sequence-derived feature currently exported.

## 2. Feature Switch

No feature re-export is needed. The shard NPZ files already contain
`embedding_pooled_vec` (see `FEATURE_SCHEMA.md`). Only the downstream feature
key changes.


Retention policy:

## 6. Why Not Salvage concat or M2

- `concat_pooled_vec` is a model-internal fusion output, not a concatenation we
  can rebuild. Its collapse is structural, not fixable by re-normalization.
- Whitening / PCA on M2 is pointless: near-zero variance directions would
  amplify numerical noise, not recover signal.
- Re-training the LucaPCycle M2 branch on our enzymes is out of scope for P0/P1
  and is tracked separately (Section 7).

## 7. Feasibility Note — Self-Built Residue-Level Feature Model

Three paths, ranked by ROI. This is a planning note only; none of them block P1.

| Path | What | Difficulty | ROI | Blocks P1? |
|---|---|---|---|---|
| A | Use ESM2-3B per-residue hidden states directly (stop pooling) | Very low | High | No |
| B | Domain-adaptive pre-training (continue MLM) of ESM2 on our enzymes | Medium-low | Highest | No |
| C | Train a LucaPCycle-style BPE Transformer from scratch | Medium-high | Low | No |

Recommendation: Path B. Path A is a zero-cost quick win (per-residue features
are already available from ESM2-3B, just not pooled). Path C reproduces the
exact failure mode that made M2 degenerate — a task-specific branch misused as
a general embedding — and is not recommended.

Key reminder: the reason M2 failed is that it was trained for a 31-class
phosphorus-cycle classifier, not as a general enzyme representation. Any
self-built model must use a representation objective (MLM / contrastive), NOT a
classification objective, or it will collapse the same way on domain-shifted
data.
