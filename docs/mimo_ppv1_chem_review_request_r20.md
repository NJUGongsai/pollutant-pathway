## 1. 冻结口径(判据五相关正文,逐字)

- 判定基础 = 实际净变化集:供体编辑一致性以**键 diff ∪ 电荷/
  立体/同位素变化集**的实际净变化判定(含 bond_stereo_change 与
  键级立体入变化集;非四面体公开列项按标签类型分开),不采信声明
  的"编辑列表"与实际不一致的自报。
- 中心判定规则(既有,未改):实际变化 ⊆ 对齐中心(direct)或
  存在联合自同构像(symmetric_equivalent)⇒ center True;**中心外
  变化 ⇒ False + extra_changes(逐原子披露)**;全部供体中心原子
  必须有映射,部分缺 ⇒ unknown。
- 区域净变化不认证供体模板/机制(表示层契约);旁证不叠加升格。

## 2. 缺口与两类变化的区别(合成例,规则级)

**例 A(纯同位素,保守方向)**:CCO → [13CH3]CO,零编辑、声明
中心在 S_C_2/S_O_1(乙醇 C–O 键位)。修复前:变化集为空而身份键
不同 ⇒ 落入"身份不同而图轴空"分支,理由码
`net_change_only_in_stereo_representation`(**误标**:同位素差异
与立体表示无关);中心 unknown、R5 retain_conditional、不提交。
**保守但归因错误。**

**例 B(混合变化,假 verified)**:真实 AtomTool(冻结协议
v43-editproto-2)把 CCO 的 S_C_2–S_O_1 single→double 得 CC=O;
合成工具返回再把**中心外** S_C_1 置 13C(plain/mapped 一致),
产物 [13CH3]C=O;声明中心 S_C_2/S_O_1、完整映射/系数/自包含
proof 合法。修复前:同位素差异不入变化集 ⇒ 变化集只含中心键/H
变化 ⇒ "实际变化 ⊆ 中心"成立 ⇒ 中心 **verified**、coverage
full、**R6 expand**、公开 submit 事件实际入库;production caller
(仅替换工具输出通道,其余全真实)同样 submitted/expand/R6。
**非保守方向:过度授信。**

两例合证:同位素轴缺失并非"只会保守",混合变化会把中心外未核
变化写成全覆盖。

## 3. 实际 caller 可达边界(必须保留的限定)

- 固定 AtomTool 协议**没有同位素编辑操作**(add_atom/break_bond/
  form_bond/change_bond_order);例 B 的 13C 是**合成工具返回**
  (测试 patch 只改 execute_edits 的**输出通道**,内部先真实调用
  AtomTool)。本仓**不宣称**原 AtomTool 正常执行会自发改变同位素
  标签,没有真实外部来源或污染物性能结论;反例证明的是**公共
  防御消费链面对完整合法合成结果时的表示契约范围核验缺陷**
  (区域变化被错误复算为全覆盖),不是工具行为或现实反应。
- `self_contained_recompute` 证明自包含输入集确定性重算自洽,
  **不证明"编辑曾被执行"**(运行事实由执行器通道 result/指纹
  绑定,见判据五 8b/冻结补写)。

## 6. 请 mimo 评判的化学口径问题

1. **同位素并入实际净变化集的判读**:按判据五"键 diff ∪ 电荷/

   表示层情形(如同一核素的书写差异)?
2. **中心外同位素变化 ⇒ center False(violated,R5v)**:按既有
   "中心外变化 ⇒ False"规则处理中心外同位素差异,化学/契约上

   (本仓不区分——身份键层面同位素是化学事实,请评)?
3. **纯同位素不再走立体码**:例 A 改为真实轴(violated,因变化
   在声明中心外)是否符合"纯同位素不得错标仅立体"?若供体声明
   中心恰好覆盖该原子,是否应 verified(本批:是——变化 ⊆ 中心)?
4. **对账边界**:同位素不进声明–执行 ops 对账(协议无该 op),
   走属性 diff + 中心范围判定——是否同意该分工?

   的两分,化学上是否还有第三类应单独处理的同位素情形
   (如同位素丢失 13→0、多原子同位素组合、D/T)?本批实现
   对这些情形按同一轴处理(0→13 与 13→0 对称入集)。
6. **不影响面声明**:本修复不新增科学门、不认证同位素计量学/
