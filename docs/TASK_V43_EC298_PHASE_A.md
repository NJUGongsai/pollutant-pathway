## 0. 执行前必须解决的口径异议

老师的任务提出了必要的归因切片，但引用的 `agent @1 +34`、引擎 Top-10 153/真空 145、`@5` 净差 −5、以及“新引擎比旧引擎弱 36 题”的前提，均来自 v1 scorer 的**引擎身份不对称**。agent 用原始 SMILES 求 `cn_identity`，引擎却直接以可能保留电荷的缓存 `product_identity` 对已经 `cn` 归一化的金标；见 [`exam.py`](../src/pathway_v43/exam.py) 的 `_engine_chunk` 和 `score_exam`。另一个问题是所谓 `pool_identities` 只由 `engine.predict(top_k=10)` 的返回值填充，不能代表完整候选池。

独立只读重算、两臂均从原始候选 SMILES 求 `cn_identity` 后，**当前整条候选计分口径**的校验锚点为：agent @1/@3/@5 = **116/128/130**；引擎 @1/@3/@5/@10 = **118/174/193/209**。同 K 差值为 **−2/−46/−63**。按修正后的 Top-10，档位是 **209 题 Top-10 命中、89 题未在已导出的 Top-10 命中**；89 题不能称为“完整池真空”。历史 v4.1 引擎 @1/@3/@5/@10 为 118/172/190/208，新旧汇总值接近，不能再将 82→118 的表面差异归因于资产域偏移。

**实施纪律**：先完成 v2 同口径重评分并书面向老师提出上述口径修正，再生成老师要求的切片、命运表和报告补丁。旧版 153/145、+34、−5 可放在“历史错误口径”审计栏，不能用于新版标题、表格分母、验收和外传结论。若老师仍要求按旧口径另附切片，必须标成 `v1_invalid_identity_diagnostic`，不得与 v2 正式结果混算。

## 2. Phase A-0：同口径重评分，先于所有归因

产出：

1. `score_v2.json`：版本、口径、输入 SHA、298 行逐题 `agent_rank`/`engine_rank`、汇总 @1/@3/@5/@10、两臂配对分类。

### A2. 50 条 `awaiting_prediction` 的命运

### A3. 决策路径贡献

产出 `decision_path_contribution.tsv`，按**持久 decision_log 和任务模式**归组：唯一 recorded 直通、竞争 recorded/`rank_candidates`、`analogy_edit`（弃答/拒绝/接纳）、`novel_proposal`。每组给题数、agent 与引擎 @1/@3/@5、配对 both/agent-only/engine-only/neither；还应有逐题明细。预期模式题数为 **112/70/66/50**，类比内结局 **28/23/15**；agent @1 分解 **64+27+0+25=116**，@5 分解 **64+27+0+39=130**。若持久日志与这些锚点不同，展示差异及证据，不凭预测 SMILES 倒推模式。

### A4. @5 损失与输出宽度

产出 `hit5_paired_attribution.tsv`：298 题一题一行，另给 engine-only 与 agent-only 的筛选视图。修正口径下 @5 是 **engine-only 82 题、agent-only 19 题，净差 −63**，不是“找 5 道丢失题”。每条 discordant 题记录引擎金标首 rank、agent 已报告候选数/来源/选中证据、原检索是否含金标（若能离线核实）、有无未选中 recorded 卡、模型排序、validation 拒因和谨慎的归因标签。标签至少区分“候选未检出”“候选检出但未报告”“模型选错”“类比弃答”“编辑拒绝”“候选虽报告但身份不匹配”“证据不足以判断”；一题可有多个事实字段，但只给一个主因且保留不确定。

报告宽度分布预期为 **0:51、1:197、2:1、3:1、4:5、5:43**。@5 两臂名义上都是前五位，故不能将 @5 差距解释为“引擎 rank 9–10 被 agent 五位上限挤出”；rank 9–10 本来不计入引擎 @5。可以披露 agent 实际多数只报一个候选所造成的**有效宽度不足**。@10 才有五位与十位上限的不对称。

## 5. 验收门槛与交付顺序

1. **封存性**：原始首跑、金标、v1 分数的 SHA 前后一致；全程零 API、零 298 引擎/agent 重跑、零预测代码修改。衍生脚本可从相同输入字节复现相同输出字节。
2. **评分性**：两臂身份同函数、同候选计数规则，298/298 对账；v2 汇总与 §2 锚点一致或逐题解释差异；旧错误口径不得出现在正式结论。
3. **归因性**：A1/A2/A3 的逐题行数及命中数对账；A4 对 82/19 个 discordant 题全覆盖；A6 调用次数与请求账对账；每条推断都能沿 run/task/decision/validation 文件回查。

交付可两批送审：**第一批先交 scorer v2、A1–A3 和老师要求的口径异议说明**；通过后交 A4–A6 与报告修订。若 A0 不通过，不启动以 v1 档位为基础的后续归因。老师文档 §七的资产移仓、主仓恢复和大 commit 整改是独立的仓库治理任务，另写任务书处理；Phase A 不做仓库历史重写或资产搬迁。
