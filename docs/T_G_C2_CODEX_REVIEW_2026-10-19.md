## 2. 阻塞项与有限回修范围

### P1-C2-01：异产物匹配能被 prefer 筛掉，披露不能替代“歧义即拒”

**原契约**：上游任务书 `:221-224` 要求中心锚定放宽后保留“歧义即拒”。设计稿 `:265-267`、`:370`、`:432` 却允许：非全等匹配产物异于选定目标时“拒或强制机读披露”。这给出了允许继续 compiled 的分支。

**程序原因**：`c2_death_cause_probe.py:261-274` 先拿到中心匹配，`:275-311` 构造度全等子集并按 prefer 筛选；当该子集非空时，其余匹配不再编辑执行，`:315-376` 的多产物检查只覆盖保留下来的匹配。因而“剩余结果唯一”不等于“全部允许匹配只有一个产物”。当度全等子集为空时，它又允许回退全部匹配，说明被筛掉的类别并未被规则全局判为非法。现行公共入口的同目标合并/异目标拒绝见 `s5b_compiler.py:934-943`、`:963-1037`。

**本轮纯合成真实执行，不属于 298 成绩**：以模板 `[CH3:1][CH2:2][OH:3] → [CH3:1][CH:2]=[O:3]` 和人工构造输入 `OCCC(O)C`，两壳层查询存在 3 个匹配，实际可得到 2 个不同目标 `CC(=O)CCO` 与 `CC(O)CC=O`：

| 纯合成控制 | 本轮真实结果 | 证明范围 |
|---|---|---|
| 两壳层 off，保留全部匹配 | `unsupported/ambiguous_alignment`，2 个不同目标 | 当前查询范围确有可执行异产物 |
| 两壳层 prefer（即 prefer2 核心） | 丢弃 2 个非全等匹配后 `compiled`，仅报 `CC(O)CC=O` | 偏好过滤隐藏了异产物，而非所有候选产物相同 |
| 现行公共 `compile_donor_template` | `unsupported/ambiguous_alignment` | 同一人工输入在既有公开入口可见歧义拒绝 |
| 仅有多取代位点 `CC(O)C` | prefer 回退全部并 `compiled` 为 `CC(C)=O` | 非全等类别不是全局禁用类，不能用“另一规则已判非法”解释丢弃 |
| 合法正控 `CCO` / 无 O 负控 `CCC` | 正控仍 `compiled` 为 `CC=O`；负控 `no_alignment` | 有效正控与中心缺失拒绝同时保留，未以全面拒绝换通过 |

### P2-C2-02：普通 Atom 的芳香旗标不等于精确双向芳香身份约束

设计 `:191` 与原型注释把查询描述为“元素＋芳香旗标＋键级”，但原型用 `Chem.Atom(atomic_num)` 与 `SetIsAromatic` 构造普通分子原子，未建立精确双向芳香谓词。结构子代理对人工构造模板 `[CH3:1][OH:2] → [CH4:1].[OH2:2]` 与输入 `Oc1ccccc1` 完整执行两壳层查询、prefer、编辑、校验及执行：非芳香 C 旗标 false 实际命中芳香 C true，prefer 回退后 `compiled` 为 `O.c1ccccc1`。

同一反例在现行公共编译入口也 compiled，因此这是既有普通 Mol 匹配的共性，**不是 C2 新引入的行为，也不据此指控 298 原型新增候选已有假阳性**。芳香键本身的匹配约束仍有价值。修正文案区分“芳香键级/芳香正向要求”与“原子芳香旗标精确双向相等”；若拟新增精确约束，需明确为规则变化并复算，否则诚实标记该保证尚未成立。该项不新开本轮工程验收门。证据同 [纯合成结果 aromatic_flag_probe](review_evidence/t_g_c2_codex_2026-10-19/structure_review/synthetic_result.json) 与 [结构专项 findings](review_evidence/t_g_c2_codex_2026-10-19/structure_review/findings.md)。
