# chain13 C 线归因大白话版（2026-10-15）

> 题域标签：**298=RHEA 通用酶学/已见题**。技术版（数字和证据全在里面）：
> `docs/CHAIN13_C_NETNEG_ATTRIBUTION_2026-10-15.md`。
> 性质：离线只读分析，没跑任何模型、没动判分。

## 一句话总结

**C 线本身不亏不赚（兜了一圈回到原点），这次掉分主要是"服务器端抽卡"的手气问题
+ 13 道题的钥匙孔根本没对上——三件事都拿出了程序证据。**

## 背景两句

- chain13 批给酶反应路径补了个新功能（C 线）：遇到需要"共底物"（反应时还得额外
  进场一种小分子，比如水）的题，自动把它供给进候选池。
- 批后一算：strict（严格全对）从 130 掉到 114，掉了 16 题。这轮就干一件事：
  这 16 题到底是谁弄丢的？

## 先上术语对照表

| 黑话 | 人话 |
|---|---|
| strict / partial / uncovered | 严格全对 / 对了一部分 / 没做出来 |
| v1 / v2 口径 | 两把不同松紧的尺子；v2 稍宽（给共底物题开后门） |
| C 门 | 新功能的开关，35 道题被它打开过 |
| 候选池 / 扩展面 | 仓库里存的"可能的反应做法"清单 / 模型+系统实际挑中去做的那部分 |
| 采样/服务端非确定性 | 同样的题问两遍，服务器（模型服务）回答不完全一样——抽卡手气 |
| fail-closed 拒绝 | 系统发现危险输入直接罢工不跑（保守拒绝） |
| run_error | 这道题的运行记录里写着"跑挂过" |
| 声明链 | "这个共底物是官方声明过的原料"的凭证记录 |

## 三个问题三个答案

### 1. C 线亏分了吗？——没有，净零

35 道被 C 门打开的题：v1 尺子先掉了 5 题（130 那批里的 strict 掉下来），
v2 尺子的豁免又把 5 题全捞回来——**24 → 19 → 24，兜一圈回到 chain12 水平**。
其中还有 2 题是白赚的（原来"没做出来"，C 线供给共底物后先到"对一半"，
v2 豁免再捞成 strict）。C 线承诺的供给→执行→参与→声明四步，35 题全部走通，
**零罢工记录**。

### 2. 那 16 题谁弄丢的？——主要"服务器抽卡"，证据链如下

263 道题 C 线根本没碰（输入一字未变），却掉了 11 题 strict。我们把这 18 道
损失题（10 道掉一半 + …，非 C 部分 18 道）在两批的"实际选中的做法清单"逐题对比：

| 证据 | 结果 | 说明 |
|---|---|---|
| 候选池（供给面） | 18/18 题两批**完全一样** | 仓库供给稳定，不是供给的锅 |
| 模型+系统实际选中的做法（扩展面） | 18/18 题**全都不一样** | 输入没变、池没变，选出来的东西变了 = 抽卡手气变了 |
| 运行记录 | 有 10 题"模型调用直接失败"（网络/服务端传输挂了） | 服务端不稳的直接实锤；另 1 题模型直接交白卷 |

诚实声明：**能证明"手气变了"，但没法证明"哪一题的丢分是哪一次手气造成的"**——
没有同批重复跑，无法对拍。这是面上归因，不是逐题定责。

### 3. 13 道"该豁免却没豁免"的题呢？——钥匙孔没对上，13/13 全是供给面没开

这 13 道题理论上该被 v2 的"共底物豁免"救回来，实际 0 兑现。查下来不是模型不想用、
也不是凭证没写，而是：

| 检查点 | 结果 |
|---|---|
| 这 13 题的候选池里，共底物候选的结局 | 297 个候选：289 个直接死在编译门（最大死因"对不上结构对应关系"141 件），6 个编译过了但没触发救援资格，2 个被合并 |
| 救援开关（rescued/declared） | 13 题**全部为 0** |
| chain13 的事件里有没有共底物参与物 | **13/13 一个都没有** → 差在"根本没进场"，不是"进场了没开凭证" |

翻译：救援机制的钥匙孔（资格条件）没罩住这 13 道题——大部分候选连门都进不来，
少数进了门的又不符合救援资格。这是**重设计的方向**：改资格面，让这批题的共底物
能进袋。（本报告只描述证据，不修代码。）

## 波动参照（防"16 题全是 C 线搞的"误读）

同协议的两臂参照（hpc2 A/B，唯一差异是一个供给开关）：两臂之间逐题状态翻转
34/298、strict 净差 ±3。本批翻转 47/298、净差 -16——确实超出寻常波动，但本批
叠了四个变量（C 供给+声明链+新尺子+预算模式），超出部分不能记在 C 线头上；
C 线自己名下的账已经查清：**净零**。

## 与任务书骨架的不一致

**零不一致**。骨架给的每个数字都对上了；仅有两处补充披露（不是矛盾）：2 个 run
没有调用记录文件（远端本来就没有，那两题零调用就挂了）；chain12 批没留身份
快照（结构差异，已如实记录）。
