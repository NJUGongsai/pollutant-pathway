# T-F 合成验证报告（大白话版，2026-10-17）

> 术语对照在文末。技术版：`docs/TF_SYNTHETIC_VALIDATION_2026-10-17.md`。

## 一句话结论

**证实了**：存在一个真实的排序缺陷——模型最喜欢的候选如果和池子里一条"没被模型排名"
的旧候选是同一个反应，它会被合并掉，**合并后那条反应排到最后**；模型排第一的选择
反而最后执行（甚至可能压根不执行）。好在真实跑过的 298 题里这个组合一次都没出现，
所以目前没有已知损失。

## 打个比方

模型像点菜：它把"novel 菜"排第一、把"池子菜 A"排第二。但厨房有个规矩——两道菜
如果是同一道反应（净反应签名相同），后来的并入先来的。novel 菜是后报的，被并进了
一条**模型压根没排过名**的池子菜 B。并的时候，novel 的"第一名"牌子没人接着，
直接扔了；B 因为没被模型排过名，按规矩只能排到所有"有名牌"的菜**后面**。
结果：模型第二想要的 A 先上，模型最想要的（现在挂在 B 名下的那道）最后才上——
排位从第 1 掉到了垫底。

## 我们怎么证明的

1. **造了个假厨房**（合成夹具）：底物用最简单的酒精（CCO），池子里放两条构造的候选
   （A 和 B），再造一条模型提案 novel:1——它的反应和 B 一模一样（代码级验证过签名相等）。
2. **让 scripted 模型只排两个名**：novel:1 第一、A 第二，B 不排名（模拟真实场景里
   "模型没提那条池子候选"）。
3. **跑完看账本**：A 拿到位次 1（model_selection）；B 拿到位次 2（deterministic_fallback
   = 没被点名只能殿后）；novel:1 消失（被合并，账上少一条）。
4. **对照组**：让模型把 B 也排名（B 第二名）→ 合并后 B 保留自己的位次，模型的第一
   选择照样先上（良性形态，真实批里 3 次折叠都是这种）；不让合并（novel 换个反应）→
   novel:1 位次 1 直达。**位次劣化只在"首位被合并 ∧ 幸存者没排名"这个组合下发生**，
   和读代码读出来的条件一模一样。

## 意味着什么

- **要修吗**：老师说这属于"排序免费收益"（修起来便宜、语义上白赚）。修法建议：合并时
  如果被合并者的名次更好，就把名次传给幸存者，并在合并记录里写清楚"传了谁的位次"。
  修好后拿今天这四个夹具当回归测试（fx1 的 B 应该变成位次 1）。
- **现在亏分吗**：不知道有亏——chain13/chain14 真实 298 题里这个组合 **0 次出现**，
  所以目前没有任何已知失分归因于它。修复是"加固"，不是"找回已丢的分"。
- **谁拍板**：修不修、什么时候修（可以搭 T-H 修复批的车）——CC 定。

## 术语对照

| 术语 | 人话 |
|---|---|
| 净反应签名 | 一个反应"本质"的指纹（看产物多重集），签名相同=同一反应 |
| 折叠/去重 | 后报的候选与先来的同签名时，并入先来的，自己不再单独存在 |
| model_selection / deterministic_fallback | 名次来源两种：模型点过名 / 没点名的按固定规则殿后 |
| effective_rank | 实际生效的执行位次（决定谁先被送去展开执行） |
| deferred | 超出执行名额时转"备选"，不保证会执行 |
| scripted 协议 | 用事先写好的"模型回答"驱动整条链——零模型调用零费用 |
| 合成夹具 | 纯构造的假输入（不碰题目/答案/语料），专为验证某个分支 |
