## 0. 大白话摘要（30 秒版）

我们的系统是"污染物/酶催化降解产物预测 agent"（确定性主干 + 三个
LLM 协议点 + 零 LLM 判分）。在 298 题酶学考卷上，最新严格判分
hit@1 = 76/298，目标线 119（40%）。失分诊断指向三个窟窿：

1. **排序**：25 题的正确答案已进候选，只排第 2-3 名；
2. **供给**：候选供给上界 U ≈ 106 题——排名做到完美也到不了 119，
   池子本身不够大（编译墙又拦掉 1,323 个候选）；
3. **语义**：204 题因辅因子/共底物判分语义卡死（我们自己的设计
   问题，已有设计轮处理，无外部工具可救，不在本次评审范围）。

我们提议接入三个现成开源件攻 ①②：**RankLLM**（LLM 重排，攻排序）、
**EVODEX**（SMIRKS 反应算子生成候选，攻供给）、**BioRGroup**
（RHEA R 基团展开数据，攻直通检索覆盖）。请 GPT 攻击这个优先级
排序与三件的具体集成方案。

## 1. 系统与现状（背景，供独立判断）

- **架构一句话**：LangGraph 确定性主干编排；LLM 只在三个协议点介入
  （候选裁决 rank_candidates / 受限编辑 analogy_edit / 无证据提案
  novel_proposal）；**判分评测零 LLM**（冻结，不可动）；候选卡片带
  来源/证据等级/版本追溯。
- **排名口径（重要）**：当前报告排序 = 事件提交/调度序（确定性
  代理），**不是**模型自报置信度。接入 RankLLM = 更换排名来源，
  属口径变更，须走新一轮预注册（先登记预期再跑，首跑不可因分数
  改写）。
- **实测轨迹**（298 题域，严格主口径 hit@1/@3/@5）：
  v1 39/72/74 → v2 29/67/89 → v3 73/100/105 → **v4 76/101/103**。
  松口径（旧架构判分习惯，作敏感性参照不当成绩）v4 = 123/179/187。
  零失败题，恰 298 次模型调用，全程 ¥17.48。
- **供给上界 U ≈ 106**：严格口径下无论怎么排序，候选池最多支撑
  约 106 题命中；hit@5=103 距 U 只剩约 3——@3/@5 侧排序余量也小。
- **语料**：corpus_v1 共 43,177 条（RHEA 约 37,100 + enviPath
  6,077）；USPTO 松弛索引 188,725；recorded 直通通道当前消费
  EAWAG 镜像 4,454。
- **编译墙**：组分级编译器拦下 1,323 个候选；内部 v4b 轮已攻坚，
  复测净 +1（低于方差判定线，按纪律缓发合批）。
- **目标线**：hit@1 ≥ 119/298（用户钦定 40% 档）。

## 3. 提议（评审对象）

### 3.1 RankLLM 先行（优先级 1：接入面最小、见效最快）

- **是什么**：castorini/rank_llm（Apache-2.0，可 pip 装）：listwise/
  pairwise/pointwise LLM 重排工具包，滑窗聚合处理长列表，专治
  "正确答案在候选里却排第 2-5 名"。
- **怎么接**：把候选卡（产物 SMILES + 证据等级 + 来源摘要）映射为
  稳定 ID 的排序请求；listwise 提示 + 滑窗；模型走我们现有
  OpenAI 兼容端点；调用计入既有预算/记账（每 run 上限 + 批级闸门）。
  判分器不动（重排发生在判分之前的候选阶段，LLM 允许）。
- **预期（诚实）**：hit@1 +5~15（25 题里翻一部分，不会全翻）。
- **风险**：①token 成本（每题加一轮 LLM，量级可控）②长列表位置
  偏置（滑窗缓解不除根）③**SMILES 当"文档"排序无文献背书**——
  RankLLM 的成熟场景是文本段落重排，分子串列表的有效性是本项目
  最大的未知数④口径变更须新预注册，且回退路径要预设计。

### 3.2 EVODEX 并行开发（优先级 2：唯一能破供给天花板的）

- **是什么**：UCB-BioE-Anderson-Lab 出品（软件 MIT，版本 2.1.0，
  装前复核）：约 8.3 万条生物催化反应（EnzymeMap + ECREACT 合并）
  提炼的反应算子库 + Python API（project_reaction_operator /
  project_evodex_operator / project_synthesis_operators /
  match_operators）。
- **怎么接**：独立候选生成适配器——底物进、算子套用、候选出，
  operator_id/软件版本/父反应映射进候选卡；作为**与现有通道并列的
  新生成通道**，不动现有通道；顺带提供绕开编译墙的独立路径。
- **预期（诚实）**：抬升 U，幅度 = 规则覆盖率 × 编译适配，跑前
  不报数。
- **风险**：①部分转化（P 类算子）不是完整净反应，证据等级必须
  低于"实验确证"——分级语义要设计②依赖兼容性未实测③与语料侧
  ECREACT 衍生内容重叠去重④数据许可装前再核。

### 3.3 BioRGroup 数据补丁（优先级 3：便宜、离线、无运行时风险）

- **是什么**：2025 Sci Data 数据集：把 RHEA 引用的约 1.3 万个含
  R 基团（"任意基团"占位符）的模糊 ChEBI 分子展开成具体结构。
- **怎么接**：纯离线语料工程——展开结构进直通检索索引；运行时
  代码零改动。
- **预期（诚实）**：直通通道对 RHEA 模糊反应的覆盖提升（298 题域
  正面打击）；幅度跑前不报数。
- **风险**：①**"展开者选择"风险**：R 基团本意是任意基团，展开成
  具体结构后直通可能匹配到"展开者的选择"而非"题目本意"——需把
  "经 R 展开命中"标为旁证级证据②数据许可待核③与 corpus_v1 的
  RHEA 部分对账去重。

### 3.4 明确不接（已裁定，除非 GPT 给出强理由翻案）

- **XGrammar**（语法约束输出）：需本地权重推理栈，我们全走 API
  模型，用不上；
- **OctoTools / REAP 整套**：是协议重设计的量级，不是"接入"；
- **Pydantic 严格契约**：工程卫生活，当前零解析失败，不流血的
  伤口先不包扎（评审如认为前瞻必要可提，但须给触发条件）。

## 4. 集成纪律（硬约束，评审建议须在此框内）

1. 判分零 LLM 冻结不动（重排/生成都在判分前，允许 LLM）；
2. 严许可：Apache-2.0/MIT 级；
3. 每次口径变更走预注册（先登记预期再跑；首跑不可因分数改写；
   失败题留分母）；
4. 证据等级如实分层：外部算子生成/经 R 展开命中均不得标实验确证；
5. 评审循环（mimo 化学评审 + Codex 工程复审）照走，结论采信到与
   程序证据互证为止。

## 5. 我们的诚实总预期

RankLLM +5~15；EVODEX 抬 U（幅度未知）；BioRGroup 直通覆盖+若干；
加上范围外的 D2 语义轮（解锁 204 题的一部分）。**三件合计能不能到
119：我们现在无把握**——这是问 GPT 的核心问题之一（Q8）。

## 6. 请逐条攻击（问题清单）

- **Q1 优先级**：在 U=106 < 119 的硬约束下，"RankLLM 先行 + EVODEX
  并行"是否最优？还是应该全力供给优先、排序后置？
- **Q2 RankLLM 集成形态**：listwise 全量替换确定性提交序，还是作为
  第二信号与提交序融合？在"口径变更须预注册 + 可回退"的纪律下，
  哪种更稳？
- **Q3 RankLLM 有效性**：SMILES 列表当排序文档，有无已知坑/同类
  工作（分子排序、化学反应排序）可参照？listwise 提示里给多少
  上下文（证据等级、来源）合适？
- **Q4 EVODEX 覆盖**：EVODEX 语料（EnzymeMap+ECREACT 生物催化）对
  RHEA 酶学题域底物的预期重叠，值得投入适配器吗？有无更好的现成

- **Q5 EVODEX 证据分级**：部分转化算子的输出在我们的候选卡里应该
  站哪一级（低于实验确证是共识，但低到哪：旁证/假设/仅提名）？
- **Q6 BioRGroup 展开风险**："展开者选择 ≠ 题目本意"的风险怎么
  控（旁证级标注够吗？还是只用于召回提示不用于直通判定）？
- **Q7 漏网之鱼**：有没有我们侦察（2026-09 扫 GitHub，结论"微生物

  工具？特别是：现成的辅因子/共底物剥离规则库或数据集（Q7b，
  若有可直接救 204 题的一部分）？
- **Q8 到线概率**：三件 + D2 合计到 hit@1 ≥ 119/298 的概率，请给
  你的判断与理由；如认为到不了，给"最可能停在哪、为什么"。
