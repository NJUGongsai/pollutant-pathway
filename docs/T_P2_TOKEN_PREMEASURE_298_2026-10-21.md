### 3.2 生产等价重建

逐题按 `runflow._run_decide`/`_call_real_fetch` 的生产路径重建：

1. `substrate_state = build_chemical_state(substrate, "raw_input",
   [{"record": f"ppv1-substrate:{run_id}"}])`；
2. `substrate_profile = build_substrate_profile(state, build_path_context(
   condition_facts=[]))`；run_input `plan` 无 `condition_facts`，故
   `representation_fidelity` = 四轴 `as_written`、`condition_keys_known=[]`；
3. `parent_path_id = stable_id("spath", run_id, "root")`（生产同源）；
4. 逐 spec `prepare_hypothesis(...)`；失败如实登记，不猜；
5. `substrate_atom_id_map` / `execution_graph_payload` /
   `build_proposals_user_payload`（`feedback_error=None`，首发固定载荷）；
6. token = system + user 两段，`add_special_tokens=false`；UTF-8 字节数
   不当 token 数。

### 3.3 standard / lean 为什么在真实池折叠

30 题合成样本的 standard/lean 是**测量脚本构造的两档 spec 复杂度**
（standard：1/3 候选带 `requirements`、约 32% 带副产物；lean：无
`requirements`、约 20% 带副产物）。真实冻结池的 spec 是只读事实，不能
删改；其形状已经是 `requirements=0`（lean 侧）而 `coproducts` 45%
（高于 standard 档）。因此真实池只有**一个合法生产读数**，
standard/lean 两列折叠为同一数字；本报告不构造合成 lean 变体去改
真实事实。作为形状敏感性，§5.1 另按真实候选数分桶、§5.4 按
“是否含副产物候选”分层披露，均未改任何 spec 内容。
