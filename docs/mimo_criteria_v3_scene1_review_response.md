## Q1 互变归一的化学边界

**结论：部分成立——但"默认配置下的轴 A"不是纯互变异构归一，而是「互变归一 + 潜在互变中心立体可抹」的联合轴；作为"同一化学个体"的字面主张，在默认配置下不成立。**

**化学论据**

1. **判等在逻辑上蕴含"参考侧立体被抹"**（纯谓词推理，无需执行）：草案登记 14 对中参考侧有立体 14/14、预测侧有立体仅 1/14，而判据是**互变归一后 canonical isomeric SMILES 逐字相等**。预测侧本来就没有立体信息，若参考侧立体描述符在归一中存活，isomeric SMILES 必然不等。⇒ 14 对全部相等，唯一可能的机制就是**参考侧的立体描述符在归一过程中被消除**。所以"救回"的成分里，"立体被擦除"不是疑点，是**判据成立的必要条件**；真正的化学问题是"被抹的立体是否本来就该被抹"。
2. **擦除半径不是"实际可互变的中心"，而是"RDKit 互变模板覆盖的原子"（潜在互变）**。RDKit 官方文档与 PR #3327 原文：`removeSp3Stereo=true` 时"立体化学信息从**参与互变的 sp3 原子**上移除——**例如所有氨基酸都会因酰胺-亚胺醇互变而失去立体**，尽管氨基酸作为立体化学稳定实体是众所周知的"；该 PR 作者明确写"保留 true 只是向后兼容，**设为 false 更可取，以避免稳定手性中心的非预期消旋**"，且 **Sitzmann 等人原始工作流对 sp3 设 false**（仅对双键立体设 true）。GitHub discussion #6852 / issue #3672 记录了同一现象的用户投诉：默认参数下**已定义的手性中心被删除**。
   ⇒ 回答你的直接疑问：擦除**不会**被限定在"化学上真正活泼的互变中心"；它会擦平**化学上构型稳定、但恰好落在互变模板反应原子集内的**立体中心（典型：氨基酸/α-羟基酸的 α-碳、羰基 α 位）。
3. **`removeBondStereo=true` 的半径同样外扩**：官方文档明示"参与互变的双键失去 E/Z——**烯醇会因酮-烯醇互变失去 E/Z 立体**"。即擦除半径覆盖到与互变体系相连的双键立体，而非仅互变原子本身。
4. **登记实践的对照**：标准 InChI 的 mobile-H 层只合并**杂原子间（N/O/S）的质子转移**，不合并酮-烯醇，也不因此抹掉氨基酸 α 手性。也就是说，物质登记层面被广泛接受的"互变归一"比 RDKit 默认配置**窄得多**。把 RDKit 默认配置等同于"登记意义上的同一化合物"，是把两个不同强度的口径混为一谈。
5. **判别性旁证（来自草案登记的布尔画像，非本人执行）**：21 条纯立体差配对在互变归一后**仍不等**，说明擦除确实是"局部于模板覆盖原子"而非全局抹立体——这否定了最坏情形（全局擦除），但**不能**证明被抹的那些中心化学上该抹。14 vs 21 的分界线，本质是"差异立体中心是否落在互变模板原子集内"，而非"立体是否可稳定存在"。

**风险**

- **R1（最大）**：预测侧漏写立体（13/14 无立体）的配对被互变轴判同一 ⇒ 系统性地**接受"互变中心处的立体缺失/甚至 L/D 写反"**。对 RHEA 酶学语境，L 与 D 的区分是真实酶学差异（存在专一的 D-氨基酸酶），把该差异交给一个"潜在互变"判据抹掉，化学上不可辩护（在默认配置下）。
- **R2**：互变体本身可作为不同代谢物/不同酶促产物登记（酮式 vs 烯醇式、内酰胺 vs 内酰亚胺、杂环 N-H 位置异构在固态/结合态下可区分）。合并作为"物质名层面"常可接受，作为"酶促产物身份"须逐类判断。
- **R3**：canonical tautomer ≠ 体系中占优势的互变体。判据取的是 RDKit 打分选出的规范形，不携带任何热力学/条件信息；据此宣布"同一化学个体"缺条件（pH、溶剂、酶活中心）维度。
- **unknown**：14 对中被抹立体原子的具体归属、互变模板原子集对这些位点的覆盖路径——**待执行验证**（只读探针即可：逐对输出"哪些立体原子在归一前后改变、是否属变换参与原子"）。

**改进建议**

1. **诚实命名**：轴 A 在默认配置下应称「互变归一（互变中心立体容忍）」，不得简称"互变归一"。
2. **双臂披露（与 B 轴两臂纪律同构）**：默认臂（removeSp3Stereo=true）与**立体保留臂**（`CleanupParameters.tautomerRemoveSp3Stereo=False`，bond stereo 按 Sitzmann 建议保持 true）同批双跑、分开报数。若立体保留臂仍能救回显著数量，"互变救回"叙事才干净。
3. **把 C1 判据化**：14 对逐对输出原子级溯源（被抹立体原子是否为变换参与原子、在规范互变体中是否仍为 sp3 立体中心），交师姐就"该位点在实际条件下立体是否可稳定存在"逐题确认。
4. **闭合口径不一致**：请求写"23 题真异构体（21 纯立体差+2 真差）"，草案 §4.4 C1 用"19 条 ISOMER-TRUE 配对"作同形画像证据——19 vs 23（或 21）的口径差未解释。负控 N1 的对象面（23 题全体）与 C1 的证据面（19 条）必须在冻结前对齐，否则负控覆盖面与风险论证不闭合。**此点为文档级缺陷，建议冻结前更正。**

## Q3 质子化轴

**结论：成立面窄而干净，是三轴里化学上最站得住的一条；误判面可控但存在两个具体形态；含碳对排除是必要保守（且不只是 V2 相容性问题）。**

**化学论据**

1. **B 轴的判据比 cn_identity 更严，不会引入新宽容**（已读源码核实）：`cn_identity = stereo_blind(uncharge(...))`（`identity.py:46-55`，电荷归一 + 立体盲）。B 轴 = Uncharge + **保留立体**的 isomeric 逐字相等 ⇒ 能过 B 轴的配对，其立体必须本来就相等。⇒ B 轴**只**抹掉质子化书写差，不抹任何立体信息。这是 A 轴不具备的干净性质。
2. **成立面**：共轭酸碱对/同一有机母体的两种书写（去质子 vs 质子化），在水相生化语境与物质登记实践中通常作同一物质处理；判据 fail-closed（净电荷差不授）方向正确。
3. **误判面 R4**：Uncharger 不具 pKa/regio 意识——它按规则盲中和可中和位点。**质子化位点异构**（如某杂环上质子分别在 N1  vs N3 的两种阳离子写法）可能被归到同一中性形而判等，掩盖"质子上错位置"这类真实书写错误。**待执行验证**：该形态在 6 题中是否存在。
4. **误判面 R5（较轻）**：真实参与态被抹——激酶/磷酸酶语境下底物的电离态（如核苷酸多阴离子）是反应式质子记账的一部分；但身份面与反应式计量面分层后，此风险主要落在叙事而非判据。
5. **漏救而非误判**：带金属反离子的盐式（Na⁺/K⁺ 等）逐组分 Uncharge 后反离子仍存留 ⇒ 不相等 ⇒ fail-closed。若 6 题中含此类，Uncharger 臂救不动；要覆盖须走 ChargeParent 臂（丢反离子）——同意草案仅作并列敏感性披露，因 ChargeParent 同时丢弃片段，抹差异的范围更大，启用须逐行披露"反离子/片段被丢弃"。

**含碳质子化对排除：必要保守，且理由比草案写的更强。** 碳酸体系（CO₂/HCO₃⁻/CO₃²⁻）的形态差异本身在 RHEA 里就是**反应参与物对**（碳酸酐酶类反应即以该对为底物/产物两侧）；把它们归一相等会**抹掉一个真实反应的两侧**，属化学计量层面的错误，而不仅是与 V2 零碳断言的相容性问题。**改进建议**：把该排除从"分子名名单"升级为**机读物种规则 + 指纹**（防名单漂移/静默扩围），并在 B 轴披露字段中登记每条排除的机读原因。

## Q4 记录侧形式归一（T-E）

**结论：作为「同一母体反应物（同一共轭酸碱对/同一有机骨架）」成立；作为「同一反应物（含电离态与反离子）」不成立——但 T-E 只作用于检索/编译对齐层、判据身份面零触碰，故成立面足以支撑该用途。三层口径分开报足以防误读，附三个前提。**

**化学论据**

1. 酸式与盐式是**同一有机母体的两种书写**；在水相反应与模板对齐（子结构匹配）语境下按母体认定合理。记录侧的反离子/电离态属于**记录的计量信息**，不属于模板检索需要的骨架信息——剥离它做对齐在化学上站得住。
2. **不对称（只归一记录侧、底物侧不动）是漏救方向的保守**，不会制造误判；但"64 行恢复全部只需归一记录侧"是单批观察，**不得外推为规则**（下一批底物侧带电离态时会漏救）。建议在披露字段登记"底物侧未施加"为覆盖限制。
3. 草案 C-4 已把 Uncharger 会**反而失配**的阳离子型记录行（如 NAD(P)⁺ 系）排除在外——这正是"盲中和真实带电参与物"的风险已被数据点名；同意该行不并入。
4. 对齐判据 `useChirality=False` ⇒ 对齐层本就不判立体，T-E 不引入新的立体误判面（这是好事，建议写进冻结文本的正交性说明）。

**三层口径防误读：足够，附三前提**

- 前提 1：③严格命中层**永不**由①②层推断；①②层永久携带"上限/非命中"标签（草案已写，同意）。
- 前提 2（新增建议）：逐行披露**归一改写了哪些原子（电荷/质子）**，并检查**模板匹配原子是否落在被改原子上**——若匹配恰好依赖被改写原子，登记为"过度对齐风险"信号行，交人工复核。
- 前提 3：T-E 改写记录字符串 ⇒ run 身份/缓存 key 的工程问题（草案 §5.3/缺口 6 已登记）必须在实施设计轮闭合，否则同批可比性被静默破坏——化学评审确认这不是判据问题但会污染判据证据链。

## Q5 正交与防泄漏

**结论：设计骨架正确（许可门 + 单归属 + 指纹 + V2 不变断言），但有 5 处化学判读层面的漏/需加固，其中 2 处为实质缺口。**

1. **【实质缺口】参数指纹必须纳入 RDKit 版本与全部 CleanupParameters**：canonical SMILES 与互变模板集**跨 RDKit 版本可变**；草案版本化纪律只写"算子及参数"，附录 A 登记了 rdkit 2026.03.6 但未明示其入指纹。建议指纹 = sha256(算子参数 + `tautomerRemoveIsotopicHs`/`tautomerReassignStereo`/`maxRestarts`/transforms 文件指纹 + RDKit 版本串)。
2. **【实质缺口】"轴间单归属 A→B 取先"缺双臂证据**：A 轴（含立体擦除）比 B 轴更宽松，取先会把"实为质子化救回/实为立体擦除救回"的配对静默记为互变。**建议**：计算上**双臂都跑**（A 臂、B 臂布尔各自落披露字段），计数上仍单归属——把"取先"从顺序依赖的归因变成有证据的归因。成本极低（6/14 题规模）。
3. **芳香拼写差 0 题**：同意草案 N2 写法；再加一条**对外表述模板级**的固定句："本批 AROMATIC-REPR=0，该轴未启用、覆盖未证"——任何"三类表示差已覆盖"的表述应判违规。
4. **许可门的化学盲区**：`strict_structure` 许可门防的是**范围越权**，不防**参考结构本身表示不全**。方向上多数 fail-closed（参考缺立体而预测有 ⇒ 归一后不等 ⇒ 不授），唯一开口仍是"立体差位于潜在互变中心"——与 Q1 结论合流，故该开口应由 Q1 的溯源/负控闭合，而不是靠许可门。
5. **缺席轴不宣称、单臂不外推**：B 轴"两臂分开报"的纪律（草案 B-2）是对的，同样纪律应施加到 A 轴（见第 2 条）；轴 C 的"对齐判据与编译层同源"是好的正交性设计，同意。

## Q6 总体读法

**最可能被误判成「同一」的是：立体异构体，且其差异立体中心恰好落在 RDKit 互变模板覆盖的 sp3 原子上（典型：氨基酸/α-羟基酸的 α-位手性、羰基 α 位）——表现为"预测漏写立体甚至 L/D 写反，被互变轴当作救回"。** 这与 14 对中 13 对"预测侧无立体"的形态完全吻合；RDKit 官方以 L-氨基酸为例明示该擦除会"非预期消旋稳定手性中心"，且原始 Sitzmann 工作流对该参数取 false。

**最优先的一条负控建议（合成手性负控，零金标、可自动构造）**：取一批含**化学稳定手性中心**的分子（L-氨基酸/α-羟基酸类），构造"仅手性反转（L→D）或仅删除该中心立体"的配对，跑 A 轴**默认配置**，期望 **0 授**。**预期该负控在默认配置下会失败（待执行验证，依据为 RDKit 官方 L-氨基酸示例与 issue #3672/#6852 记录）** ⇒ 它应作为档 B 的准入闸门，并直接决定轴 A 是否必须改用立体保留配置或窄化为杂原子 mobile-H 臂。现有 N1（23 题真异构体）只能覆盖"本批已出现的立体位置"，覆盖面窄于该合成负控，二者不可互相替代。

**关于"归一提升的 strict 计入 headline"**：在**默认配置**下，这不应表述为「测量修正」——测量修正指的是修 bug 型的口径回归；而本轴的救回与"立体容忍放宽"在机制上不可分，属**判据容忍度变更**。只有在立体保留配置下仍成立的那部分救回，才有资格叫"测量修正"。故我的读法：**本轮先走档 A 出披露数；若立体保留臂 + 手性负控 + 师姐逐题确认三项全过，再以"strict 语义已变更（带 token）"的名义谈档 B**；在此之前任何 headline 上升都应表述为"判据变更的待验效应"。

### 总体读法（≤5 行）

轴 B（质子化）最干净，可推进；轴 C（记录侧）层位正确，补一条"匹配原子 vs 被改原子"披露即可。轴 A 的默认配置在化学上过宽：它判等的前提就是参考侧立体被抹，且擦除半径覆盖化学稳定手性中心（RDKit 官方自证）。建议本轮三轴全部走披露档（档 A/上限口径），档 B 冻结条件绑定"立体保留主臂 + 合成手性负控 0 授 + 师姐逐题确认"。所有数字保留 298/post-hoc 单批标签，26 题仅为毛上限，不得作任何预期收益表述。
