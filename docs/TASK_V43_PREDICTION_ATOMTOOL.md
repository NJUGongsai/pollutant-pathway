# v4.3 第二阶段实现任务书：PredictionAgent、AtomTool 与预测接线

> 交给独立执行模型实现；本会话负责 review。目标仓：`/Volumes/CC/Enzyme_Agent/dependingv43/`。第一阶段确定性主干与资产接线是本任务的基线，先读 `ARCHITECTURE.md`、`REPO_DESIGN.md`、`docs/TASK_V43_CORE_WORKFLOW.md`、`docs/CORE_WORKFLOW_REPORT.md` 和现有代码。

## 0. 目标与边界

让现有 `awaiting_prediction` 路径能在 LangGraph 中继续：基于**当前路径的完整祖先链**和 ReactionFinder 的证据，执行竞争候选裁决、类比反应编辑或无证据提案；经 AtomTool 和确定性校验后，将通过的反应事件提交 PathwayStore，再按既有预算与 frontier 策略探索。保持“每步最多报告五个候选”与“实际只展开选中的路径”分离。

不重写已验收的 ReactionFinder 排序或资产，不改旧仓，不跑冻结 eval/298 外考，不把模型输出直接写成化学事实。`recorded_reaction` 的唯一可接受命中仍走原确定性通路；规则应用与类比证据仍须挂牌为预测，不能改称实测。

## 1. 先解决证据可用性

目前检索卡的 `atom_mapping` 可为 `unavailable`，而引擎候选不一定携带可定位的原始供体反应。实现前建立**可复核的类比来源适配**：从已校验的 `assets/analog/` 或本仓其他实际读取文件中，以稳定 ID 找回来源反应物、产物、映射和反应中心；记录所用文件、SHA256、行/记录 ID、映射质量。对无法找回或无法对齐当前分子的卡明确标 `mapping_unavailable`，不得凭候选产物或来源字符串编造映射。若需给检索卡补字段，保持已有 schema 的兼容读取，并给新字段升版本。

把“检索引擎已经给出一个产物”与“模型完成了类比编辑”分开记录。前者是可供排序的规则/类比候选；只有具备有效供体映射和当前分子对齐时才进入受限 `analogy_edit`。映射失败的路径仍可依策略尝试其他证据或受约束新提案，拒因必须留痕。

## 2. 任务书与输出契约

PredictionTask 使用版本化 JSON，至少含 `run_id`、`task_id`、`path_id`、根底物和当前分子的原始/规范 SMILES、按时间顺序的完整祖先链（每步父/子、反应事件与证据 ID）、环境条件、当前检索产物引用和哈希、候选及来源层级、已有兄弟路径、深度/frontier/LLM/提案剩余额度。由 PathwayStore 和不可变检索产物确定性组装，不能仅传当前分子，也不能靠 `S211` 一类显示名推断来路。

明确区分三种任务协议和提示词：

| 模式 | 输入与模型职责 | 输出 |
|---|---|---|
| `rank_candidates` | 多条已记录反应竞争，或规则候选需适用性/顺序裁决；保留每条来源及条件 | 证据 ID、候选顺序、选择/暂缓/拒绝理由；不得虚构结构或改写已记录产物 |
| `analogy_edit` | 当前分子、完整路径、可追溯的供体反应及已对齐映射、AtomTool 的 MoleCode | 受限原子/键编辑、引用的映射和证据、目标 MoleCode 与 SMILES、理由 |
| `novel_proposal` | 无可用记录/规则/类比，或映射失败后策略允许的受约束提案 | 最多五个有序产物、反应说明和不确定性；全部标为新提案 |

模型响应另存原文引用、结构化解析结果、模型/提示词/参数版本、请求输入哈希、调用状态、耗时和用量。解析失败、超时、空响应和不合法证据 ID 是显式结果；重试次数有上限。模型不得自行宣布“确切命中”、实验条件相容或校准概率。

## 3. AtomTool 与确定性校验

以 v4 的 `molecode_render.py`、`vendor/molecode` 及其测试为参考，先记录来源和许可，再封装本仓 `AtomTool`。它负责 SMILES → 带稳定原子标识的 MoleCode、MoleCode → SMILES、往返身份核对、原子映射/编辑操作复验。明确测试 MoleCode 对手性、电荷、芳香性、同位素、断键/成键及多组分的表示能力；有损或不支持的情况要拒绝并给原因，不能悄悄用未经验证的 SMILES 替代。

候选进入 PathwayStore 前统一通过：RDKit 解析/价态、编辑引用的原子与键是否存在、映射一致性、反应方向、按反应类型允许的元素变化、路径内循环、兄弟去重、终点与预算、来源/条件标签。原子守恒和环境外源氧等按明确规则检查并记录例外依据，不把简单元素计数当作机理证明。一个反应的多个产物仍属于同一 ReactionEvent；无效候选单独保留拒因，不能使有效同组产物失去来源。

## 4. LangGraph、存储与恢复

在现有 `classify_evidence → mark_awaiting_prediction` 处接预测分支，最终汇入 `validate_products → commit_pathway → select_frontier`；模型不可直接修改 State、SQLite 路径账本或 frontier。State 只增加任务/预测/校验产物引用和预算快照。模型未配置时，既有确定性流程继续可运行，并明确停在 `awaiting_prediction`。

预测任务、响应、解析结果、校验结果分别落不可变 `results/<task_id>/` JSON；外部调用前先查同键产物，避免检查点重放造成重复计费。同键由路径、当前分子、检索产物哈希、预测模式、模型/提示词/策略版本决定。对于“请求已发出但响应未落盘”的中断，不得默默重试并声称恰好一次；要有持久调用状态、请求幂等键（提供者支持时传入）及可审计的重试/人工处理策略。PathwayStore 提交仍使用事务和幂等键，重复提交不能生成第二条路径。

明确处理第一阶段已完成且停在 `awaiting_prediction` 的 run：提供**显式**继续/迁移入口，或清楚规定从相同输入开新 run；不能静默改写旧 `run_identity.json` 或把旧 checkpoint 当作新图版本直接恢复。新 run identity 必须锁定模型、提示词、MoleCode 实现、资产与策略版本；新运行中的 `resume` 要核对这些身份。README 给出无模型、假模型和真实提供者（有凭证时）的命令与产物位置；密钥只从环境变量读取。

## 5. 验收用例

1. 用合成路径 `Substrate → S11 → S211`，证明发给模型的是该 `path_id` 的两步祖先链及每步证据；同一分子经不同来路到达时，两份任务不能串线。
2. 多条已记录反应竞争：模型只能选择/排序现有反应；每条反应的多产物保持同一事件；未选候选和理由仍在报告中。唯一已记录反应不触发 LLM。
3. 规则候选、可映射类比、不可映射类比、完全无证据分别进入正确协议；类比编辑用可核对供体映射和 MoleCode 往返，缺映射不能假成功。
4. 无效结构、价态错误、映射错位、重复兄弟、路径循环、条件冲突、表示往返有损、预算不足和终点锁定都有明确拒因，不污染账本。
5. 假模型计数器与进程中断夹具覆盖响应落盘后/事件提交后恢复：没有重复外部调用或重复事件；请求发出但无响应的悬空状态按文档处理。
6. 真实资产烟测至少覆盖一条当前 `awaiting_prediction` 路径；逐卡核对 evidence/asset 哈希，记录模型有无配置时的实际 stop_reason、候选与提交结果。真实提供者不可用时如实标明未实测；不能用假模型结果冒充在线模型验证。
7. 第一阶段测试与 21/21 资产清单校验继续通过；新增测试能在无凭证环境运行。报告测试数、环境版本、运行命令及一份可查看的 `runs/<run_id>/report/pathway.json`。

## 6. 交付给 reviewer

在 `docs/PREDICTION_ATOMTOOL_REPORT.md` 列出协议/schema、来源映射覆盖率与缺口、MoleCode 往返结果、每类路由的实际产物、恢复前后调用/事件/路径计数、运行身份、完整测试输出、已知限制。review 硬门槛是：完整路径进入任务；证据层级与来源准确；类比映射可追溯；模型提案经确定性门禁；预算及恢复可复核；旧主干不回归。
