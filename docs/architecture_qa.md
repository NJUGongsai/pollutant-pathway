## Q1:v4.2 的工作流程是什么?有几个 agent?

### 答:只有 1 个 agent,一人分饰两岗

v4.2 里真正称得上「agent」的只有一个 LLM 大脑:**deepseek-v4.1-flash**(外采 API,温度 0,冻结不训练)。它一个人干两份工:

1. **裁决官**(第二段):给引擎挑出来的候选排序、剪枝;
2. **编辑**(第三段):规则库搞不定的地方,亲自动笔写产物。

为什么只有一个?设计时拍过板:多 agent 各带上下文会互相打架,改成「单人格、每步开一场新鲜短对话」——岗位不同,脑子是同一个。

其余部件都**不是 agent**:引擎是规则+检索系统(外采语料,冻结);MPNN 是自训小神经网络,只打「位点得分」且是低权重参考(P0.5 诊断后降权);类比桥是纯检索,零 LLM。

### 六步流程(以一道 298 考题为例:阿特拉津第一步产物是什么)

1. **出题**:底物 SMILES 喂给系统,要求给出有序产物候选列表;
2. **引擎海选(不花 LLM 的钱)**:v3 引擎翻规则库+相似反应检索,捞出候选池(如 131 个),按分排队,前 5 名(beam=5)进路径树。**顺序铁律:引擎先出候选,LLM 后裁决**——不是先猜位点再找规则;
3. **大脑第一岗·精排**:候选连证据卡打包给 LLM 排序剪枝;
4. **大脑第二岗·编辑**:对规则搞不定的地方,LLM 写提案(详见 Q2);
5. **四道门安检**:提案逐道过检(详见 Q2);
6. **交卷判分**:根节点候选顺序=答案列表,确定性判分器(零 LLM)按 cn 身份对金标打分,出 hit@1/3/5。

### v4.1 → v4.2 改了什么(三个开关)

| 环节 | v4.1 | v4.2 |
|---|---|---|
| 精排能动第一名吗 | 不许(保守铁律,代码钉死) | 能(record 档,留痕) |
| 编辑岗什么时候开口 | 只问引擎完全空手的节点 | 每题根节点都问(root_always) |
| 查重范围 | 全树(误杀过金标) | 只跟同父兄弟比 |

**必须记住的背景**:上一场 298 考试实际是「多步超支」跑法(每题 ~28 步),考卷钦定单步——修复的收益在**单步场景**论证成立(counterfactual +5/−0 等),在多步 dev 上反而小幅变差(S3 门 FAIL)。下一件事 = 单步口径 dev 对照。

## Q2:编辑岗(大脑第二岗)的详细工序

五道工序:**什么时候开口 → 备料 → 动笔 → 安检 → 收编**。

### 工序一:什么时候开口(触发规则)

- **v4.1**:只有「空手节点」被问——引擎海选时一个带规则的候选都没捞到的分子。考卷事故:39 道真空题里 30 题的根节点因「池子里多少捞到了点东西」不算空手,**编辑岗全程没开口,LLM 连题都没见到**;
- **v4.2**(root_always):每道题根节点**必问一次**——规则覆盖再好也问,多花的只是一次调用。

### 工序二:开口前备料(证据卡)

材料里最理想的是**类比卡**:类比桥(analog.py)去两个库(USPTO 放宽索引 18.9 万条 + 语料模板 1.7 万条)找「跟这个底物长得像的反应是怎么变的」,整理成卡片(变换前后骨架+反应中心)。

298 实况:全卷桥只成功产卡 3 次(127 次没触发、11 次空手)——**编辑岗基本「裸脑」在写**。这正是 v2 任务书要改革的:先让卡能被找到(救题模板 rank 165+ 的可发现性问题),编辑岗才有弹药。

### 工序三:LLM 动笔

大脑收到:当前分子 + 类比卡(如果有)+ 岗位说明(提示词写死格式与保守条款)。输出**提案**:一个或多个「这一步会变成什么」,用 MoleCode 完整表示法写,附理由(有卡引卡号)。

历史坑:早期大脑在 molecode 模式输出纯 SMILES,格式不对全被第一道门拒(68/71 拒因都是它);后改内容自动探测双格式才治好——现在的「提案 194 个全过门零被拒」就是那次修复的成果。

### 工序四:四道门安检(写了不算,要过检)

1. **合法性**:RDKit 能解析、化合价合理;
2. **守恒**:降解方向允许「掉元素」(掉甲基、断键都行),**不许凭空多出**底物里没有的元素;
3. **白名单/状态**:产物须是系统认识的合法化学实体状态;
4. **查重**:旧规矩跟**全树**比——同分子在树里任何角落出现过就拒;v4.2 改**只跟亲兄弟比**(同父节点下已有才算重复)。

ATP 三题是第四道门的经典案例:金标 AMP,大脑一字不差写出 AMP,但树第 5 层深处早有个死节点也是 AMP,旧规矩一票否决——提案被毙,答案永远出不了分。v4.2 兄弟查重就是给这个开口子。

### 工序五:收编

- 过门提案**追加到引擎候选后面**(引擎选中的排前面,提案垫后——P5 修过的排序规矩,防提案插队挤掉对的答案);
- 全被拒:v4.1 登记死端;v4.2 只留痕不登记(根节点还有引擎候选垫着,不该判死)。

**留痕**:每次开口、桥给没给卡、每条提案生死、大脑原话全进 decision_log——「30 题没被问」「AMP 被毙」这些结论全靠这份账挖出来。

### 一句话总结

编辑岗 = 「引擎不会做的题,给大脑一次执笔机会,写完过四道安检,过了也只能坐引擎的后排」。v4.2 = 让它被问到更多(每题必问)+ 安检不再误伤(兄弟查重)+ 精排岗放开首位——收益在单步考卷论证成立,多步 dev 未兑现,待单步对照验证。

## Q3:每步 top-5,整条链推下来是 5ⁿ 条路线吗?

### 答:对一半——是「每步 top-5 的一棵树」,不是「5ⁿ 条路线的枚举」

**对的部分**:链条确实拆成单步反应逐步推;每个节点扩展时引擎取 top-5(beam=5)进树;理论上限确实是 5ⁿ。

**要修正的部分——三道闸让实际远小于 5ⁿ**:

1. **同分子合并**:不管从哪条路过来的,同一个分子(cn 身份相同)在树里**只占一个节点**——建的是「图」不是「树」,很多理论路线中途汇合(A→B→C 与 A→D→C 到 C 并成一条);
2. **硬预算封顶**:max_nodes=200、max_expands=50、max_depth=12——算账:5 叉树 12 层理论 **2.4 亿条路线**,真枚举一张考卷就烧穿,所以节点总数 200 封顶;
3. **死端剪枝 + 终点锁**:展开不下去的分支直接停。

**实际规模**:多步一场树约 50-200 个节点(实测单题 26-113),可达路线几百条封顶,与 5ⁿ 差几个数量级;单步考卷(298 钦定)更极端:根节点只展开一次,**5 个候选、5 条「路线」**,无爆炸问题。

**评测怎么算**(因为是树不是单路线):
- hit@K 看**每一步的排名**(金标在不在该步 top-K);
- 路线召回看**金标路径在图里通不通**;
- spurious 看**树里多少节点不在金标路线上**(cascade 的 0.92 = 「洪泛树 91.7% 是乱枝」的量化)。

**架构寓意**:引擎负责**把树铺宽**(宁多乱枝也要召回),大脑负责**剪枝排序**(把 5 个候选排对顺序),5ⁿ 的爆炸交给预算闸门——三班各干各的。
