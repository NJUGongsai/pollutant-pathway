# 修复报告·大白话版:上次四组实验到底坏在哪、修了什么、怎么证明修好了

> 配套技术版:[EC298_PHASE_D_R1_REPAIR_REPORT.md](EC298_PHASE_D_R1_REPAIR_REPORT.md)。
> 这版不讲术语细节,只讲发生了什么、为什么、现在可信什么。

## 一句话总结

上次 dev 20 四组实验(9-28 早上)的"成绩下降"**不算数**——系统在记分前就坏
了两处,52/80 条路线根本没跑完就被记了 0 分。这次把两处都修好、把"没跑完
不能算完成"写成硬规矩,并用不带钥匙的自动化测试 + 一次真实小实验证明修
好了。**可以进入 298 题复测**(结果标"事后修复核查",不能吹成独立验证)。

## 坏了两处,分别是什么

**坏处一:存档文件"存完自己变样"(50 条路线中招)。**
系统每做一步决策都存一个 JSON 文件,并存了一张"指纹"(哈希)。指纹是按
存档**前**的内容算的;但文件里有个"原子编号对照表"用了数字当键
(2 号、11 号),存成文件后键自动变成文字("2"、"11"),而文字排序是
"11"排在"2"前面——重新读文件算指纹就对不上了。系统以为文件被改过
(其实没被改),就把这条路线整个判死、按 0 分交卷。**模型其实答了,
是记账的把答案扔了。**

**坏处二:一个"提前退出"的出口接错了管子(pb_0117 中招 2 条)。**
有一道题(pb_0117)走到"用相似反应物类比"那一步时,程序发现要用的
"供体材料"不在检索结果清单里,于是按设计想"安全停下、留个原因"。
但流程图的下一站是固定接"调用模型"的——停不下来,直接闯进了调用站。
调用站一看手里没有任务单(空号),拿"None"当字典查,当场崩溃
(就是日志里那句看不懂的 `TypeError`)。

**为什么只有 pb_0117 崩?** 只有它恰好走到"相似检索选中 + 材料不在清单"
这个组合;对照组(C0)没开相似检索,自然碰不到。

## 修了什么(四件事)

1. **指纹问题**:存档前把数字键统一转文字键(上次当晚已修补,这次补齐了
   整链验证:存了再读、读了再存,指纹不变;故意改一个字必须被抓)。
2. **pb_0117 崩溃**:三处一起修——①"选中的供体"现在自带完整材料清单
   (不再依赖检索结果里有没有那张卡);②流程图改成"没任务单就回主循环",
   不再硬闯调用站;③就算再有人闯进调用站,报的也是带编号的结构化错误
   (能定位),不是一句天书。另外:崩溃时的完整现场(traceback)以前不
   保存,这次也存了——这次排查费劲就是因为没存。
3. **"跑没跑完"的硬规矩**:批次报告以前不管死活都写"completed"。现在每条
   路线分五类(成功/合法停/异常失败/导出失败/没跑完),任一条异常失败,
   整批就标 failed;配对比较前先过"完整性门",不过门只能出"带标记的
   部分诊断",**不能宣布谁赢谁输**。
4. **钱账**:上次报的 ¥2.75 只是"有回执的那部分"的小计——还有 50 次调用
   超时没回执,不知道花了多少。现在逐次调用一行账(发了没、成没成、有没有
   用量),没回执的部分单列"保守预留",并在拿服务商账单核对之前**不许
   把费用门报绿**。

## 怎么证明修好了

- **自动化测试 456 项全绿**(原有 413 + 新增 43),Chenyu 远端同样跑过
  (远端缺 2 个旧脚本导致的 5 个失败,补传后全过,和这次修复无关)。
- **拿事故现场原题做小实验**:pb_0117 的原题材料再跑一遍——同样的
  "相似检索选中"情形,这次存档指纹稳定、流程正常走完、答卷正常导出。
  另一道题跑了 3 次真实模型调用,其中 1 次超时、重试成功——正好演练了
  "超时怎么记账"的新规则。花费约几分钱,单独登记。
- **老数据一行没动**:上次四组的原始文件全部按哈希封存,想查随时能对。

## 现在能信什么、不能信什么

- ✅ 能信:系统不再自毁答卷;崩溃会留全现场;没跑完的批次冒充不了完成;
  钱账不虚报。
- ❌ 不能信:上次"D-3 比 C0 差"的结论(污染数据,作废);
  "修复让 D-3 变好"也**同样没验证过**——这正是下一轮 298 复测要答的问题。
- ⚠️ 复测注意:298 题都被我们看过/分析过,所以结果只能叫"事后修复核查",
  不能当独立外部验证;两臂(C0 关闭相似检索 / D-3 开启)除了这个开关,
  代码、资产、预算、模型、评分器完全相同;总并发不超 40。
