## 1. 我的建议

**保留 criteria-v2 主口径，先补齐“答案能否由所提编辑支持”和“评分究竟在哪一步失配”两项证据；随后优先实施已冻结设计的证据卡 v2，作为第一个选择层实验候选。recorded 硬优先、删副产物、放宽归一化 strict 均不直接上线。**

优化分为四条有先后关系的工作线：

| 顺序 | 工作线 | 要解决的问题 | 进入下一步的条件 |
|---|---|---|---|
| P0 | 补诊断、明确执行证明范围 | 分清排名、执行不一致、参与物覆盖与编译拒绝；复用已完成的 Stage 0 | 诊断开关不改变候选、提交顺序及原判分；缺口能定位到候选和阶段 |
| P1 | 合约与答案对账 | 合法候选不被单个坏条目拖死；声明产物与实际执行有可核对应 | 合成正负控闭合；硬门的适用范围与 unknown 处置明确，单独验收 |
| P2 | 选择层单变量实验 | 已有正确候选为什么没排到第一 | 优先证据卡 v2；新排序规则须有新证据，不能重复已失败的机械键 |
| P3 | 覆盖与供给工程 | 缺少合法产物、真实多报／少报、检索或编译漏失 | 按 P0 的具体原因分别立项，不按拒绝条数直接排投资顺序 |

**判据研究另开一条线**：互变异构／质子化归一是否构成合理的评价口径，可以研究，但不能用“放宽评分后过线”证明原系统能力提高。答案对账也可能使成绩降低，应作为效度修复汇报。

## 4. 目标架构：候选事实、执行证据、提交位次可追踪

建议形成这条链路：**建池 → 单候选准备与校验 → 模型提案 → 确定性执行对账 → 明确候选证明范围 → 排序／准入 → 提交完整事件 → 独立评分**。
其中执行对账先以旁路披露实现；将来若移到提交前并影响排序／准入，必须作为独立行为改动。可缓存确定性执行结果，但缓存键须绑定 spec、底物、工具及身份版本，正式消费时验证一致，不能拿旧结果替代重核。

| 层 | 应保留的事实 | 约束 |
|---|---|---|
| 候选登记 | 来源、spec 身份、编译版本、检索／编译阶段、原始与规范化排名来源 | 区分显式 rank、缺席/null 默认补齐、显式空、继承与 fallback；无法恢复的旧字段写 unknown |
| 执行证明 | 实际生成组分、声明生成组分、执行期望、copy 来源、主产物归属、未核范围 | `consistent / inconsistent / unknown / not_applicable` 分开，不把 unknown 当通过或确定错误 |
| 排序决策 | 原顺序、新顺序、规则版本、采用的候选事实、原因 | 不消费金标、参考匹配结果、题号特判；记录来源本身不等于反应正确 |
| 事件与展开 | 完整参与物与 occurrence／计量语义；展开／延后计划另存 | 不为凑 exact 删除真实组分；不把未展开当未生成 |
| 评分诊断 | 必要节点缺口、两侧 extra／missing、coverage、scope、豁免失败原因、匹配事件位次 | 评分侧参考诊断只留受控评测环境；不得回流成为单题生成或排序特征 |

### 产物对账必须比较什么

1. 将**声明为实际生成的产物组分**与执行碎片，按同源严格结构身份、组分多重集对账；保持主产物归属，不用字符串相等或 CN 同值代替。
2. 再核对 execution expectation 与实际结果；现有 donor／center 审计继续保留。产物一致只证明这一局部事实，不能扩大为机制或生物可行性证明。
3. 记录声明的 copy 组分单独核来源与 NC-9／NC-10，不假装经过 edits 生成；不得因“未执行 copy”直接拒绝合法记录。
4. 初期仅披露。后续硬门只拒适用范围内**已证不一致**的候选；unknown 保留其未核范围。探索性 conditional 的保留、对外答案的投影与“已验证”声明须有明确区分，任何改变现提交集的方案均另测。
