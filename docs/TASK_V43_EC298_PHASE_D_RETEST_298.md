## 3. 费用、速率与并发

1. 执行者仍须刷新并保存当日提供方**实际**模型价格、区域、RPM/TPM；旧 `2026-09-25` 快照只能作历史记录。**用户 2026-09-29 指令：不设预算上限**——不设每臂或合计费用硬上限、不设 issued 次数停止线，不得以费用或额度预估阻断发车、停止发新调用或中断运行；配额耗尽导致的调用失败按路线失败如实归档，不触发任何费用门。记账纪律不变：逐调用记 issued、响应/超时/传输失败/孤儿与 usage；缺 usage 的调用按保守预留登记；未知费用不得用已知 usage 小计填成总费用；运行结束后以服务商账单回填核对。
2. 两臂**顺序运行**，避免共享资源相互干扰。每臂最多 40 个题目 worker、全局最多 **40 个真实 API 请求同时在途**；两臂不得同时各开 40。共享 RPM/TPM/费用闸门持久化，超时、重试、失败响应、孤儿调用和烟测全部计调用与费用账。`OMP_NUM_THREADS=1`；远端长任务落盘保活，以短连接查看进度。
3. 按上次任务书的 40 并发要求，对确实需要模型的不同 qid 先完成本地准备；在额度与提供方限额允许时，通过请求发车屏障争取 40 个真实调用同时在途。记录 request_id/qid、发出与结束时间、状态、usage，算正常提供方响应的实测峰值。若自然需模型题数、限流或资源约束使峰值不到 40，报告实际峰值与原因；**不为凑数字让 recorded 题调用模型、不发伪请求或重复请求**。并发达标与否单列工程验收，不替代 298 配对完整性门。

## 4. 运行、恢复和封存

1. C0、D-3 均使用修复后的同一 `run_exam_agent` / 批次协调器路径。每题稳定 qid 显式映射至 run_id、独立账本/results；不能用目录名字符串切割推断 qid。模型响应、decision、validation、提交事件及 export 均保持原有哈希与来源引用。原始 rule/analog 卡不能直接占报告位；recorded 直通和类比编辑仍走各自既定资格/门禁。
2. 每臂按冻结 qid 顺序补位至 298 个合法终态。`completed`、`awaiting_prediction`、按规则触顶的 `budget_exhausted` 等合法停因可以形成全/空答卷并计入 298 分母；`failed`、导出失败、缺失或未终止不能被空行或部分行“补成成功”。逐题保存 stop_reason、`failed`、`export_ok`、`answer_kind`、预测 SHA、调用与 usage 状态。
3. 共享代码/配置不变的基础设施中断可按同一身份安全 resume：已持久化响应不重复请求，悬空调用记孤儿和费用预留，旧不可变产物不覆盖。若发现需改代码/配置才能继续，旧批次标 `incomplete` 并封存，新版本用**新批次身份和新目录**重做两臂；不得把新旧答卷或不同代码版本拼成一个配对集。
4. 每臂正式归并前校验原始清单与 298 个终态、唯一 qid、身份/资产/配置一致、逐路线导出 SHA、merged SHA。可输出固定 298 行便于诊断，但有异常失败时批次状态必须为 `incomplete`，并阻断**正式配对结论**。在同身份可安全恢复且全部终态合法之前，任何分数只能标 `diagnostic_incomplete`，失败题仍留在 298 分母，不做“剔题后命中率”。
5. 两臂都通过完整性门后，先封存各自 batch identity、运行事实、merged 答卷、费用账和 SHA；复核是否有凭证或金标字段意外进入运行产物。**封存后才开放金标给 scorer**。

## 5. 评分、配对与解释

1. 使用 Phase A 的正式 `v43-ec298-scorer-2`，两臂均从原始候选 SMILES 现算 `cn_identity`；整条候选字符串为主口径，多组分任一组分命中只作另表敏感性分析。主分母固定 298，空答、合法停待预测和预算终止均算未命中；不可解析候选仍占名次。`hit@10` 对每步最多五位的 agent 等于 @5，只作宽度说明。两次评分传入同一个经 SHA 核实的引擎结果文件；若选择不传引擎文件，配对只读取 `agent_rank`，不得解释缺失引擎输入时生成的 engine/tier 字段。
2. 评分器分别生成 C0 和 D-3 的 298 行逐题 `agent_rank`，输入答卷与金标 SHA 入结果。配对器按**显式 qid**联结，逐题列两臂 rank、@1/@3/@5 命中、首位产物及来源、是否空答/停因、report_rank、已验证候选数、调用/重试/孤儿、usage 与费用状态。每个 K 汇总 `both / C0_only / D3_only / neither`、D-3 的题级赢/输/平、命中数差和百分点差；四格和须为 298。不得用旧首跑或引擎分数代替本轮 C0。
3. 如需同卷引擎作背景参照，只有引擎代码/资产及输入 SHA 与封存引擎臂一致时才可复用；否则另跑零 API 引擎臂并清楚标注版本。它**不参与 C0/D-3 主配对**。不得把封存 `pool_identities` 称为完整候选池；它只覆盖导出的 Top-10。
4. 逐题差异分析将 D1 新召回、实际供体评估、资格/歧义、类比/novel/recorded 路由、验证拒因与最终报告位次分层，并附事件/卡/validation 引用。相似度增加、applicable 增加或模型自述原因均不能替代报告产物命中证据；单次真实模型抽样也不能证明确定性因果。
5. 本轮结果即使 D-3 胜出，也只能得出“**在已见 298 题、这次冻结配置下观察到的差异**”。不得用本轮逐题答案继续调 D1 阈值、排序、预算、prompt 后再次称为独立验证；`reactant_similar_enabled` 默认仍为 `false`。如需改变发布默认值，另提独立数据与发布审查。
