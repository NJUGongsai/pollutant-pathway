## M1（四物种分类的化学立场）

**一句话结论：二分法方向站得住，但"簿记噪音 vs 机制信息"这个按分子类别的分法不够准——正确的轴是三条判据；据此我明确表态：产物侧 Pi/PPi 可进豁免面（r28 A2 已裁同款，带 P 追溯），反应物侧 Pi/PPi 不享受 H₂O 同等待遇（维持 r28 A2"共底物=机制主张"），而现行拟冻结文本未写方向，必须补方向限定后才可冻结。**

展开：

| 判据 | H₂O | H⁺ | Pi/PPi（产物侧） | Pi/PPi（反应物侧） |
|---|---|---|---|---|
| ① 参考侧系统性剥除（豁免才有对象） | ✓ | ✓ | ✓ | ✓ |
| ② 机制内容可从严格比较面复原 | ✓ 水解/水合与否由产物集决定 | ✓ 电子载体 NAD(P)/O₂ 不豁免，氧化还原信息在别处 | ✓ 磷酸化/磷酸酶产物身份在严格比较面 | **部分**——见下 |
| ③ 洗白防线（声明绑定+可追溯非空洞） | O 追溯近乎恒真 | 追溯空洞但风险≈0 | **P 追溯非空洞、有效** | **追溯自指空洞** |

- **H₂O 的豁免许可来自"溶剂活度≈1"这个热力学性质**（水相反应恒有水可用，"A+H₂O→B"与"A→B"确是同一主张的两种记账法，老师附录原句成立）。**这个性质 Pi/PPi 不具备**——磷酸根浓度是真实实验条件，不是背景。所以"与 H₂O 是否同构"的答案是：**不同构**，H₂O 是溶剂背景，Pi/PPi 是分子试剂。
- **反应物侧 Pi/PPi 丢的是一个具体的机制判别子**：无机磷酰供体身份（Pi 依赖 vs PPi 依赖 vs ATP 依赖）与磷解依赖性。具体反例：`A + PPi → A-P + Pi` 与 `A + Pi → A-P` 在"Pi/PPi 双侧全豁"下产物集都塌成 `{A-P}`、反应物塌成 `{A}`，两条不同酶学主张不可区分；而 ATP 不在清单内，ATP 依赖那条仍可见——**丢的恰好只有"无机磷酰供体"这一个判别轴**。另加 r28 A6 点名的"半套簿记"假命中形态（酰基-CoA 合成酶型：丢 ATP/CoA 只留 PPi 产物）在反应物侧无磷源时**正是靠 P 追溯拦住**，而反应物侧 Pi/PPi 的追溯是自指的（P 来源就是它自己）⇒ 防线在这一侧失效。
- **r28 A2 我的原裁**："Pi/PPi 磷酸酶/磷酸三酯酶真实产物，白名单+P 可追溯；**作反应物（激酶）不豁免**"。老师 b 档条件 2 明文允许 teacher 逐项拍板反应物侧清单，故这是**合法改判，但须显式写"推翻 r28 A2 反应物侧条款"**，不能靠"簿记噪音类"标签悄悄覆盖。
- **H⁺ 我同意进**：本管线里多余的 H⁺ 是质子化/电荷记账，而电荷账在判据二本就是 unknown——豁免它不丢任何已知轴的信息（风险见 M4 的 `[H]` 身份事故项）。
- 两处**分类措辞过宽**（不阻断，登记）：① NH₃ 被归"机制信息类"化学上偏硬——产物侧 NH₃ 是脱氨的真实产物，r28 A2 原本允许带 N 追溯豁免；老师保守收窄是**范围选择**，理由应写"收窄范围"而非"机制签名"，免得 v2 讨论时被这顶帽子误导。② 机器挡板"含碳身份构造非法"会把 r28 A2 曾建议白名单的 **CO₂/HCO₃⁻/CO₃²⁻ 挡在门外**（含碳）——与 v1 清单无冲突，但须登记为已知的未来 v2 冲突点（CN⁻/SCN⁻ 在恒不忽略族，一致 ✓）。

## M3（条件 7 互斥读法）

**一句话结论：互斥读法方向对，但只封住"同一份豁免被两档重复计账"这个算术空隙；它封不住三个真实口子——二分不完备、判定谓词未定、T1′ 档零实施——须逐条落字才真双轨不重叠。**

1. **算术上本就不双计**：两档的动作都是"从比较集里减掉该身份"，幂等；所以双轨的真正风险不是重复扣减，而是**同一身份被路由到不同强度的防线上**（声明绑定 vs 元素追溯），以及**披露归因不清**。落字要求：豁免披露按（边、身份、侧）给出**且断言恰好一个 tier 标签**，机器断言"单归属"。
2. **二分不完备（本项最实）**：条件 7 只给了两个格子——"已声明的**共底物**"与"**未声明**的多余产物"。**"已声明的多余产物"两边都不在**：记录方程里声明的产物侧 H₂O/PPi（探针 4 个 PPi 极可能是这一类）按字面落入空隙。必须改成完备二分：*每一条多余参与物 =（记录已声明 ∧ 侧别一致 ⇒ v1 档）或（未声明 ⇒ T1′ 档）*，无第三态。
3. **谓词粒度决定会不会洗方向错**：若"已声明"按**身份**判，模型把记录里反应物侧的 H₂O 写到产物侧（方向错）仍会被 v1 吸收（因 H₂O 从事件两侧都会被滤掉 ⇒ 仍 exact）。须写死：**声明绑定是（身份 + 侧 + 角色）级**，侧别翻转的参与物既不进 v1 也不进 T1′，维持 partial。
4. **T1′ 档现为零实施**（r34 复核 `coproduct_ignore_tier` src 零命中，待复核）⇒ "未声明多余产物走 T1′ 忽略档"在 v1 生效期内**实际等于"维持 partial"**。这是 fail-closed 的安全方向，但必须写成明句，否则实现者可能把它理解为"应当实施 T1′ 以补齐二分"。
5. **条件 1 的执法点缺证据（缺什么先说）**：`reference_graph.py` 与 `evaluation.py` 全文未见任何记录"参考剥除了什么/记录声明了什么"的字段（`omitted_coproduct_scope`/`exempted_*` 全仓 src 零命中，读码事实）。若不指明执法对象（如经边 `provenance_refs` 回联 corpus 记录），**"未声明永不豁免"只能是文本条款**，v1 实际会退化成纯身份豁免——恰好等于探针模拟的那种（只查族）；这正是 r32 CS4a 风险 1"文本封死 + 未装配的机器"的第三次复现位。
