【Q1】结论：**成立（有条件）**——条件是命名改掉 + "少写不扣"表述修正。
理由：
1. 结构性矛盾属实：参考声明 298/298 `partial`、只含 substrate+principal_product，审计模块对同类清单判 CHECK_UNKNOWN，判分却要求集合恰好相等——尺子和参考口径自相矛盾（已核对，与既有 r22/r32 评审记录一致）。
2. extras 75% 来自系统自己喂的池条目，继续惩罚模型等于让模型为供给侧买单（请求方数据）。
3. 129 道真错里 104 道骨架不同、25 道严格身份不同，新判据下全部不翻转——"真错判对"的系统性风险在**本批实测为零**（已核对分类结构；翻转集合只来自 superset 类）。
4. 保留条件：判据放宽是尺子变更，按本仓惯例须走预注册 + 冻结 + 评审流程，不能方向裁定完直接改 `evaluation.py`。
风险等级：**低-中**（零成本重放可回滚；风险在流程与表述，不在本批数据）。

【Q2】结论：**会诱导退化，必须保留完整性激励（作披露指标，不作判对条件）**。
理由：
1. 从"集合相等"改为"子集命中"后，模型没有动机再写共底物/副产物——化学账变薄换同样的分。
2. 请求方自提的"完整性作为独立披露指标"方向正确：superset/partial_subset 诊断桶继续输出、逐题 extras 清单落盘，但不进判对条件。
3. 建议加一条护栏：披露指标设报警阈值（如 extras 数/题 环比显著上升即触发人工抽审），防"判对口径静默变松、化学口径静默变坏"无人发现。
风险等级：**中**。

【Q3】结论：**值得做，但必须先小样本对照，不支持直接全量**。
理由：
1. 现状属实：池条目无人类语言反应类型，"加 1 个氧=羟基化"全靠模型自推——补上这层语义是真实的认知减负。
2. 但 531 条候选的 LLM 命名正确率**没有任何基线**；名字起错 = 系统性误导，比没有名字更糟。
3. 最小验证：先抽 20-30 条候选送化学评审（mimo 场景 1 通道）核命名质量；通过后做 30-50 题小样本对照（同模型同池，唯一变量 = ±reaction_type），再决定全量。
4. R3 捷径风险缓解：命名只写"一级类+二级说明+低置信标注"，不写机制细节，把"看名字选"的信息量压到最小。
风险等级：**中**。

【Q4】结论：**混合模式当前不可行；synthesized 应后置，第一版只做筛选/rerank（from_database）**。
理由：
1. R1 的 8.6%（12/140）是"可执行**且**产物正确"的联合率——如果干跑门只查可执行，注入的 synthesized 条目可能可执行但产物错，**污染池而非增强池**。
2. "干跑门"必要但不充分；要开 synthesized 还需产物正确性校验，而产物正确性在 agent 写新反应的场景下没有参考可比对，只能靠化学规则评审——成本远高于收益。
3. 且 R1 的分母是"参考反应转协议"，agent 从零写协议只会更难——8.6% 是乐观上界。
4. 候选都不靠谱时允许自己写——这个口子在本批 60 道空池题上有真实需求，但正确解法是先修检索/模板覆盖，不是让 agent 裸写协议。
风险等级：**高（若开 synthesized）/ 低-中（若仅 rerank）**。

【Q5】结论：**分三步。推荐最小可归因方案如下**：

| 步 | 内容 | 成本 | 验证口径 |
|---|---|---|---|
| 1 | 判据重算（改名后新开版本），v2/新判据双列对照，**不改任何生成侧** | 零成本重放 | 零漂移门：298/298 逐题只有 superset 类翻转，重放对基线一致（请求方称已实测——**待执行验证**落盘证据） |
| 2 | 小样本 reaction_type 对照（Q3 方案）→ 通过后全量一批 | ~30-50 题调用 + 1 批 | 同池同模型 ±reaction_type 双臂；全量批与步 1 基线比 hit@1/hit@3 |
| 3 | pool agent 第一版 = **rerank 定位**（from_database only）一批 | 1 批 + agent 调用 | 对步 2 基线，主攻 47 题"答对没选对位"，看 hit@1 增量；strict 不应降 |

理由：一次全上 = R4 归因不可拆坐实；判据重算零成本零风险，没有任何理由和生成侧改动捆绑。

【Q6】结论：**有，而且应该先做**：只做改动 A（判据重算 + 完整性独立披露），不动池、不上 agent。
理由：
1. 这一步零成本拿到 52.35% 口径上限 + 47 题排序瓶颈的精确定位——信息量最大、风险为零。
2. 改动 C 的 rerank 甚至可以先不上 LLM：先分析 47 题的位次失败模式（extras 多的排前面了？），很可能一条**确定性排序规则**（如参与物精简度/命中产物数优先）就能吃掉一部分——便宜、可复现、可归因，不行再上 agent。
3. "只做 reaction_type 不做 agent"也是合理子集，但优先级低于改动 A。

【Q7】结论：**同意。主要杠杆已转向排序/位次；改动 C 应定位 rerank，不推荐生成**。
理由：
1. 47 题（strict 156 − hit@1 109）是**已测量的收益上限**；hit@1 从 36.58% 到 52.35% 有 15.8 个点的确定空间。
2. 生成新反应的收益未知，且被 R1（8.6%）+ 60 道空池题之外"池非空但没做对"的 129 道真错双重压制——生成侧的上限大概率低于 rerank 的 47 题确定空间。
3. 预期收益差异：rerank 上限 = 47 题（+15.8pp hit@1），代价一次调用/题；生成上限未知，代价 = 可执行性门 + 正确性校验 + 污染风险。
4. 推荐定位：**rerank from_database**，synthesized 通道关闭，待 Q4 的产物正确性校验有方案后再议。
风险等级：**低**（rerank 只动排序不动物语）。
